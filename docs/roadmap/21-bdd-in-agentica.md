## Phase 21: BDD in Agentica

Specified in [`docs/future/31-bdd-in-agentica.md` section 31](../future/31-bdd-in-agentica.md#31-bdd-in-agentica). This is a catch-up item of 7h (order step 7.1): BDD on the VM, written in Agentica as `std/bdd` and a runner program, after TLS and HTTP 20a and before HTTP 20b to 20d, then 7i (order decided by the user on 2026-10-13). It needs only 20a, which is done. Six PRs in order. Each one is self-contained: its own tests and docs, and it does not rely on a later PR for validation (the stacked-PR rule). The first five add pieces that nothing user-facing uses yet; 21f switches `agentica test` over and removes the old BDD.

- [x] 21a `Process.spawn_captured` and `Process.output` with the `ProcessOutput` record (§31.9), in `vm/process.c` (Linux): the working directory, stdout and stderr read all the time into 1 MiB buffers, the truncated mark and its read error (every stdout read fails once either stream is truncated, a waiting read wakes with it, a zero-byte `read_bytes` returns it at once), `Process.output` without consuming, and every close of a captured child (`Process.close`, the close after a stream-I/O timeout or an oversized line, the end-of-run cleanup) sending `SIGTERM`, then `SIGKILL` after one second from a libuv timer, never blocking the VM (only the end-of-run cleanup waits, bounded, as today); a relative command still resolves against the VM's directory, not `dir`. Catalog entries in `src/builtins.rkt` marked VM-only, lowering import keys (appended, no format bump); the fallback in `src/main.rkt` and `read-program` in `src/bdd-runner.rkt` refuse a program that calls them (`LOWER-UNSUPPORTED`), so the frozen evaluator never sees them. Tests: golden `process-captured-*` fixtures (working directory, a relative command resolved against the VM's directory, stderr kept, partial reads then `Process.output`, 2 MiB truncation and its read error, the zero-byte probe after a stderr flood, the not-captured error), and Racket tests that a `read_line` timeout on a captured VM child that started a sleeping grandchild leaves no grandchild behind, and that `Process.close` does the same. Docs: `grammar.md` (Processes), the programming skill's `references/processes.md`, `site/content/library/process.md`, `docs/vm/10-io-tls-processes-http.md` §10.4 ("As built"), `CHANGELOG.md`.
- [x] 21b `Task.pending_count()` (§31.9): `pending_tasks` in `vm/task.c` made public, catalog entry marked VM-only like 21a. Tests: a golden `task-pending-count` fixture. Docs: `grammar.md` (Lightweight tasks), `references/tasks.md`, `site/content/library/task.md`, `CHANGELOG.md`.
- [ ] 21c The Gherkin parser in Agentica, `stdlib/bdd/gherkin.agc`, registered in `src/stdlib.rkt` as `std/bdd/gherkin.agc` (§31.3): the same subset, codes, first error and locations as `src/gherkin.rkt`, returning a value or one diagnostic. Internal: importable through `std/` like every registered module, but unsupported; not in the programming skill or the site; no import guard. Tests: golden `bdd-gherkin-*` fixtures with every case of `tests/gherkin-test.rkt`. Docs: the development skill (where the BDD pieces live).
- [ ] 21d Matching, `stdlib/bdd/match.agc` (§31.4), and the canonical JSON rule (§31.8): pattern compiling with `RUNTIME-BDD-PATTERN`, whole-text matching with backtracking, quoted-capture decoding, undefined, ambiguous and duplicate checks; `grammar.md` (JSON) pins that a parsed object encodes with its keys sorted and de-duplicated (the last duplicate wins), as `vm/json.c` already does, so `JSON.encode(JSON.parse(x))` is canonical and no JSON parser is written in Agentica. Internal module. Tests: golden `bdd-match-*` fixtures and a `json-canonical` fixture. Docs: `grammar.md`, the programming skill's JSON reference, the development skill.
- [ ] 21e The report, `stdlib/bdd/report.agc` (§31.6): the JSON report in today's shape, the plain and `--ai` text of `format-bdd-report`, and the exit code. Internal. Tests: golden `bdd-report-*` fixtures from a synthetic run. Docs: the development skill.
- [ ] 21f The switch (§31.5 to §31.8, §31.10, §31.12): `stdlib/bdd.agc` (the context API, `BDD.run` with its list and scenario modes, the predefined steps) and `stdlib/bdd/runner.agc` (discovery, the list child, a child VM per scenario with the record protocol, the `pattern` check of each step line, the `Task.pending_count` check on entry to `BDD.run` and after each handler, the output probes, deadlines, the report); `src/bdd-driver.rkt` for `agentica test` (one `--steps` program or the embedded default, two compiles, a private temporary directory, the runner VM started without `AGENTICA_VM_METRICS` and `AGENTICA_VM_METRICS_FILE` in its environment, the infrastructure report); `src/main.rkt` only parses and calls it. Deletes `src/bdd.rkt`, `src/bdd-runner.rkt`, `src/gherkin.rkt`, `tests/gherkin-test.rkt`, the `BDD.*` builtins and the evaluator's BDD dispatch (the VM-only refusal of 21a goes with `read-program`; the one in the fallback stays until 7i deletes the fallback); the checker gets the import help for `BDD.`. Tests: every case of §31.11 over the CLI, `tests/bdd/handlers.agc` migrated, `make test-bdd`. Docs: the migration list of §31.10 (`grammar.md`, `docs/bdd.md`, the programming skill, the site, the development skill, `AGENTS.md`, `README.md`, `CHANGELOG.md` with the breaking changes), and the 7h BDD item ticked.

**Done when:** `agentica test tests/bdd/specs/ --steps tests/bdd/handlers.agc` passes with no Racket evaluator involved, a handler that crashes, exits or loops fails only its scenario, and no file requires `src/bdd.rkt`, `src/bdd-runner.rkt` or `src/gherkin.rkt`. Then 7i deletes the evaluator.
