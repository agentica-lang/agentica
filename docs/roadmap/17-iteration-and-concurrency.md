## Phase 17: Iteration and concurrent collections

Specified in [`docs/future/27-iteration-and-concurrency.md` section 27](../future/27-iteration-and-concurrency.md#27-iteration-and-concurrent-collections), with the one-way principle of §25 and its table of one form for each job. Order step 7.5: new features after 7i (order 7.2), VM-only, after the items of order step 7.4, because 17a uses the checker rule of 15i (`try` in a block whose result is `Result[T]`, §25.9). Neither item needs faster lists (8d) or the prelude (order step 8.2): both are C builtins, under the library rule's exception 1 (time) for 17a and exception 4 (its own memory layout) for 17b, and both park tasks, which only the scheduler can do (§27.1 and §27.2, "Where it lives"). One PR per item, 17a first, each with `grammar.md`, the programming skill (`references/tasks.md`), the site pages, the development skill's notes, the `docs/vm/` sections named in §27, and tests that assert codes and spans (checker tests, golden VM fixtures, site examples, and hermetic I/O tests against a Python counterpart on port 0). Section 27.3 (lazy streams) adds no item: it is to evaluate later, with its criteria. Section 27.4 adds no item: its help hints come with 17a and 17b.

- [ ] 17a `Task.map(items, limit, timeout_ms) do |x| ... end` (§27.1): bounded concurrency (`limit` 1 to 1024, `RUNTIME-INVALID-COUNT`), a per-item timeout (`RUNTIME-INVALID-DURATION` when not positive), one `Result` per item in input order, the block's `error` does not stop the others, a timed-out item and its descendant tasks are cancelled, and `Task.await` on a cancelled task is `RUNTIME-TASK-CANCELLED`. VM: the builtin and its group object, and task cancellation (`agc_task_cancel`, parent and children links on each task); appended builtin, no format bump. Hints for `Task.async_stream`, `Task.async`, `Parallel.map` and `Thread.new`. Tests: the checker tests, golden fixtures and C tests of §27.1, `tests/vm-task-map-test.rkt` (concurrency bound, timing with safe bounds, timeout and cancellation) and the Python `http.server` counterpart. Docs: `grammar.md` ("Lightweight tasks", §7 hints), `references/tasks.md` and `references/diagnostics.md`, `site/content/library/task.md` and `site/content/tour/tasks.md`, `docs/vm/10-io-scheduler.md` §10.2.1 and `docs/vm/10-io-multicore.md` §10.2.3.
- [ ] 17b `Channel[T]` (§27.2): `Channel.new(capacity)`, `send(value, timeout_ms) -> Result[Void]`, `recv(timeout_ms) -> Result[T]`, `close`, `closed?`; bounded only (capacity 1 to 1,048,576), FIFO, required timeouts (0 means do not wait), no lost values under cancellation. New code `CHECK-EXPECTED-TYPE` for `Channel.new` without an expected type. Breaking change: `Channel` becomes a reserved name (`CHECK-REDEFINED-NAME`; say so in the changelog). VM: `vm/channel.c` (ring buffer, wait FIFOs, park with retry on a timer-only job, as the handle lock does), cancelled waiters leave their FIFO; appended builtins, no format bump. Hints for `Enumerator.new`, `Fiber.new`, `xs.lazy`, `Agent`, `Mutex.new` and `SizedQueue.new` (§27.4). Tests: the checker tests, golden fixtures and C tests of §27.2, with a socket handed to a worker against a Python TCP counterpart on port 0. Docs: `grammar.md` (channels, reserved names, §7 hints), `references/tasks.md` (pipeline, fan-in and owner-task patterns) and `references/diagnostics.md`, the site's task pages (or a new `site/content/library/channel.md`), `docs/vm/10-io-scheduler.md` §10.2.1 and §10.2.2, `docs/vm/10-io-multicore.md` §10.2.3; `docs/future/08-concurrency.md` then keeps only its open questions.
- Not in this phase: lazy streams (§27.3, to evaluate later), a public `Task.cancel` and a timeout on `Task.await` (open in §8), `select` over several channels (§27.2, "Left out"). CPU speed-ups from `Task.map` come only with the multicore schedulers (7h item, gated at order step 11); a CPU-bound `Task.map` program joins round 2 of the benchmarks (phase 12) as evidence for that decision.

**Done when:** the site examples of both items run on the VM; the `http.server` test shows `Task.map` running 8 delayed requests in about the time of one; a timed-out item leaves no task running; a producer, workers and collector pipeline runs with fixed output; and an evaluation round shows agents pick `Task.map` for list fan-out and channels for pipelines, with the hints of §27.4 leading them away from generators, `Agent` and locks.
