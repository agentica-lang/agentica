## Phase 7: Bytecode VM

Replace the tree-walking evaluator with a bytecode VM written in C with the
Boehm GC, step by step, without changing the language. The front end (lexer,
parser, module linker, checker, in `compiler/`) lowers the checked program to a
typed intermediate form (IR), then to bytecode that the VM runs.

Why a VM and not a transpiler or LLVM IR: agents write, run and repair in a
loop, so start-up time matters more than peak speed, and users should not need a
compiler toolchain. A VM keeps `--max-steps`, the call-depth limit and located
runtime diagnostics almost for free. Transpiling to C can come later from the
same IR if native binaries are needed. Why C with Boehm: C is small, fast to
build and available everywhere, and the VM can ship as one binary (OpenSSL is
vendored and linked statically, `docs/vm/10-dependencies-and-platforms.md`
10.0). The Boehm GC removes manual memory management from the VM and runtime, so
values can be shared freely without reference counting. The cost is that the
runtime (tasks, files, processes, TLS, HTTP, JSON) must be written in C, so
memory safety depends on discipline and tooling (sanitizers, fuzzing of the
loader).

Rules for every subphase:

- The language does not change. `grammar.md` stays the contract. The VM is the
  only backend and the reference; 7i deleted the Racket evaluator.
- Catch-up work is tested with golden outputs
  (`tests/fixtures/vm/<name>.expected`, rewritten by `make goldens` with a
  reviewed diff) and independent Node/Python peers
  (`docs/vm/README.md` §1). A runaway program stops with `RUNTIME-STEP-LIMIT`
  under `--max-steps`. VM messages must be clear for agents, which evaluation
  rounds judge.
- New features are VM-only.
- The compiler may optimize freely as long as the exit code, stdout, program
  stderr and diagnostic codes in the goldens stay the same: inlining, constant
  folding, common subexpression elimination, loop-invariant code motion, and
  merging or moving `STEP`s (a runaway loop must still hit `RUNTIME-STEP-LIMIT`;
  step counts may change).
- Diagnostic codes stay stable. The VM reports `RUNTIME-` diagnostics with the
  original source span.
- No placeholder files, directories or opcodes for later subphases.
- C naming: every exported function, type and global of the VM library uses the
  `agc_` prefix (`agc_value`, `agc_vm_run`); macros and enum constants use
  `AGC_` (`AGC_OP_ADD`). File-local helpers are `static`, so they need no
  prefix.

  switch. TLS crypto stays on the I/O thread (moving it to the schedulers is a

  fixtures with `--schedulers 4`, under TSan when available (`make vm-tsan`,
  `make vm-tsan-run`; TSan does not get along with Boehm's stop-the-world, so

  build is covered only by a GC-stress run with `--schedulers 4`. With N=1 the
  black-box parity rule stays, and the differential, golden and seeded tests

  smoke tests and BDD runs that use tasks run with `--schedulers 1`, or must not

real program, not on micro-benchmarks. The start-up numbers are also a baseline

change, not part of `make test` or CI, and no timing thresholds.

- [ ] A load driver under `benchmarks/` (Python standard library only) that

  task in the server that loops on CPU (and one that calls a long builtin), to

  program.

### 7k: Review what the VM inherited from Racket

Order step 8, after faster lists (8d) and next to the 7g hot spots. The first VM
PRs copied Racket's behavior exactly; the goldens (phase 7 rules) hold only the
exit code, stdout, program stderr and diagnostic codes, so keep a copied rule
only where it is good on its own.

- [ ] Lowering optimizations in the `compiler/` lowering, now allowed
  (the list is in the phase 7 rules). Each lands with a benchmark number before
  and after (`make bench`, `docs/vm-benchmarks.md`).
- [ ] `Map.delete` is O(n): `agc_map_delete_hash` in `vm/map.c` copies the
  reversed key list up to the deleted key. Keep insertion order but use a
  structure with O(log n) delete, for example the persistent ordered map planned
  for `Table`, or an index-tagged HAMT plus tombstones compacted later.
- [ ] Own clear error messages instead of Racket text leaking through: for
  example `File.read_text`'s `bytes->string/utf-8: ... byte string: #"..."`
  (Racket byte-string syntax) and `File.write_bytes`'s `network: bytes must
  be ...` prefix. Review `docs/vm/02-reference-behavior.md` §2.8 and the JSON
  messages. Diagnostic codes stay. An error string a program prints is program
  data (`docs/vm/README.md` §1): the PR that changes a message switches the
  fixtures that print it to printing only ok or error (or a stable kind).
- [ ] Unicode tables generated from the official Unicode Character Database
  (UCD) files, pinned to a Unicode version, instead of Racket 9.3's output (see
  the header of `vm/unicode_data.c`).
- [ ] The 4096-byte per-handle file buffer with Racket's flush rule
  (`docs/vm/02-reference-behavior.md` §2.8) and other I/O ordering copied from
  Racket: keep each only where it is a good rule on its own.
