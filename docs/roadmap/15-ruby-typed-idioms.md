## Phase 15: Ruby typed idioms

Specified in [`docs/future/25-ruby-typed-idioms.md` section 25](../future/25-ruby-typed-idioms.md#25-ruby-typed-idioms), Part A, with its principle of one way to do each thing. Every item comes after 7i deletes the evaluator (order 7.2), changes the front end and `src/lower.rkt`, and runs on the C VM only, never on the Racket evaluator. Three order steps: 15a (front end only) as the first item of order step 7.3, before `std/log` (14c), so `std/log` ships with a `fields` default and no `_with` functions; 15b to 15e, 15i and 15j at order step 7.4; the prelude part, 15f and 15k, at order step 8.2, after faster lists (8d), because on today's flat-array lists an Agentica loop that builds a list is O(n²). One small PR per item, each with `grammar.md`, the programming skill, the site page, the development skill's notes and tests (parser, lexer and checker tests that assert codes and spans, golden VM fixtures, site examples). The items are independent, except where noted. Library items follow the library rule (after the order table): their code is Agentica in the compiler prelude, and the only new builtins are `String.compare` (public, under its exception 5), `File.eof?` (public, under its exception 1), and the internal `__fail_arg` and `__float_fixed` (prelude-only, guarded by the loader). Part B (§25.12) and Part C (§25.13) add no items. Nine items are planned; 15g and 15h are not planned.

- [ ] 15a Order step 7.3, first item, before 14c. Default parameter values (§25.1): `CHECK-DEFAULT-ORDER`, `CHECK-DEFAULT-VALUE`, `CHECK-ARITY` with a range; `lower.rkt` fills the missing arguments at the call site; the linker resolves an enum default in the declaring module. Docs: `grammar.md`, the programming skill (with `references/diagnostics.md`), `site/content/tour/functions.md`.
- [ ] 15b Re-exports `export Alias.name` (§25.2), in the linker (`src/modules.rkt`) only. Docs: `grammar.md`, `references/modules.md`, `site/content/tour/modules.md`.
- [ ] 15c Struct update `value.with(field: x)` (§25.3). The ban on `Fn` fields named `with` comes here, in advance, so that 10a stays non-breaking; the ban on a type-parameter field named `with` is in 10c. Breaking change: an `Fn` field named `with` becomes `CHECK-REDEFINED-NAME` (say so in the changelog). Docs: `grammar.md`, the programming skill, `site/content/tour/structs.md`.
- [ ] 15d Value equality for structs, enums, lists, maps and Results (§25.4): the checker rule and the VM's `EQ`/`NE` opcodes with an explicit stack; a bytecode format version bump (an opcode's meaning changes). Docs: `grammar.md`, the programming skill, `site/content/tour/structs.md`, `lists.md` and `maps.md`, `results-and-try.md`, `enums-and-case.md`, `site/content/library/result.md`, `docs/vm/03-ir-and-bytecode.md` §4.2 (`EQ` and `NE`), `docs/vm/10-io-scheduler.md` §10.2.1 ("`==` only on scalars, strings and ranges").
- [ ] 15e Standalone lambdas `lambda do |x: Int| ... end` (§25.5). In the lexer, parser, checker and lowering. A `lambda` literal as the last argument where a trailing block is accepted (named, builtin, method and import-alias calls; not `.call(...)`) is `CHECK-BLOCK-TARGET` with the trailing-block help (tests for it, for `g.call(1, lambda do |x: Int| x end)` and for the valid places). Breaking change: `lambda` becomes a reserved word (say so in the changelog). Docs: `grammar.md` (and its §7 hint row), the programming skill (and its adapter examples), `site/content/tour/blocks.md` and the site's adapter examples, section 11.4, and `docs/future/15-adapters-and-json-inspection.md` (once lambdas land, the `getter`/`putter` helpers there are replaced by `lambda`).
- [ ] 15f Order step 8.2, after 8d. The compiler prelude and the Enumerable methods on `List` and `Map` (§25.6), with no new aliases: `select`, `collect`, `detect`, `inject` and `reject` get `CHECK-UNKNOWN-METHOD` with the canonical form. Adds the public builtin `String.compare(a, b) -> Int` (-1, 0 or 1, by code point, as `sort`) for String keys of `min_by`/`max_by`; a NaN key never wins unless every key is NaN, and ties go to the first element (tests for both). The prelude modules are always linked, checked once at build time with the result cached next to the embedded source, and `lower.rkt` emits only the prelude functions the checked program reaches. Runtime errors in prelude code are reported at the user's call or argument (the outermost frame of the innermost run of prelude frames; `__fail_arg`, a prelude-only intrinsic), and prelude frames are skipped in stack traces. User calls into the prelude, and prelude calls of the user's `Fn`, never lower to `tail-call`. Every prelude function is O(n) plus callbacks on the 8d lists (`push`, `set` and indexing O(log32 n)): bodies build with `push` or on `map`/`filter`/`reduce`, never call `concat`, `take`, `drop`, `reverse`, `sort`, `sort_by`, `Map.keys`, `Map.values` or `Map.delete` in a loop (a lint test checks this), list each cost in the `grammar.md` table, and have a 100,000-element golden with its step count. A bytecode format version bump: `src/bytecode.rkt` writes a prelude flag on each function, the argument spans on prelude calls, and one name-only source entry per prelude file whose single span every prelude instruction uses; the VM replaces that span at run time in every reader of spans (step limit, runtime diagnostics, tracing, stack traces); `__fail_arg` is a builtin that the loader (`vm/loader.c`) rejects outside prelude functions. Docs: `grammar.md`, `references/builtins.md`, `site/content/library/list.md`, `map.md` and `string.md`, the development skill, `docs/vm/03-ir-and-bytecode.md` (with the §4.5 sentence "There are no internal helper builtins") and `docs/vm/08-loader-and-cli.md`.
- 15g `unless` and 15h statement modifiers: not planned, see §25.13 (second ways to write `if`; `unless c` gets a help that shows `if !c ... end`, and section 11's help for modifiers stays).
- [ ] 15i `File.open(path, mode, timeout_ms) do |f| ... end` closes the handle when the block ends (§25.9), and the builtin `File.eof?(handle, timeout_ms) -> Result[Bool]`, so the canonical example does not match error text; the block form becomes the canonical way to use a file handle in the skill and the site. Docs: `grammar.md`, `references/files.md`, `site/content/library/files.md`.
- [ ] 15j Heredocs `<<~NAME` (§25.10): the lexer, with today's token kinds and a `heredoc?` field on the token, carried to the parser's string node as a flag (added here); `LEX-UNTERMINATED-HEREDOC`, `LEX-HEREDOC-INDENT`, `LEX-HEREDOC-ONE-LINE` (a heredoc is the canonical form for two or more lines); a heredoc in a `case` pattern or an import path is `PARSE-UNEXPECTED-TOKEN`. Docs: `grammar.md`, the programming skill (with `references/diagnostics.md`), `site/content/tour/strings.md`.
- [ ] 15k Order step 8.2, after 15f. `format("...", args)` with a literal format checked at compile time (§25.11): `CHECK-FORMAT-LITERAL` (also for a heredoc), `CHECK-FORMAT-SPEC`, a catalog entry for `format` with a "checker-handled, variadic" marker (so the linker keeps the name in imported modules), the prelude `format.agc` and the prelude-only `__float_fixed` builtin (a catalog entry with the prelude-only flag, like `__fail_arg`); bare `%s`/`%d` formats get a help that shows interpolation (`CHECK-FORMAT-SPEC`). Breaking change: a user `def format` becomes `CHECK-REDEFINED-NAME` (say so in the changelog). Docs: `grammar.md`, `references/builtins.md` and `references/diagnostics.md`, `site/content/library/string.md` and `numbers.md`, `docs/vm/03-ir-and-bytecode.md` §4.5 ("There are no internal helper builtins").

**Done when:** each item's site examples run on the VM, and an evaluation round shows the new forms checked and used by agents with the same diagnostic quality as the forms they replace.
