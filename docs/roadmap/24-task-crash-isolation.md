## Phase 24: Task crash isolation

Specified in [`docs/future/37-task-crash-isolation.md` section 37](../future/37-task-crash-isolation.md#37-task-crash-isolation). Phase 24 is VM work with a small language change: a runtime error in a task other than `main` ends only that task. Its place in the order is row 7.1 of the [roadmap](README.md). It has one PR, with its own tests and docs. The semantics are a proposal for the owner to review.

- [x] **24a: crashes end only their task (§37.3 to §37.8).**
  - **VM:**
    - `agc_vm_run` (`vm/task.c`) sets the failure target once per turn; a fatal outcome (a crash in `main`, `RUNTIME-STEP-LIMIT`, `RUNTIME-INTERNAL`, an exit) ends the run as today, anything else crashes the current task;
    - the crash, in the order of §37.8: finish the turn, store and print the diagnostic (text, `--ai`, `--json` with `"task": true`), cancel the descendants (20b's `agc_task_cancel`), close the owned handles and channels by kind, pass on a `next_owner` turn, wake the awaiters;
    - owners on user-visible handles only (file, socket, listener, process, server; not the process guard or job resources); a handle passed directly as the `Task.spawn` argument moves to the new task (nested ones and channels do not); `HttpClient` exempt;
    - the close per kind (§37.5): mark closing and wake every lock waiter with the closed error; files by an `OP_CLOSE` pool job, pending while a job holds them (run by `agc_io_finish`, or where 20b releases a detached holder); sockets, listeners and TLS by `disown`; processes by `close_proc`, never `release_proc`; servers by `close_server`;
    - the two `Task.await` entries; the `Result` entry gives `error("task: cancelled")` for any cancelled task; a crashed task counts as done for `Task.pending_count`;
    - `Task.unobserved_crash()`; a run whose `main` returns with an unobserved crash exits 1 with one summary line;
    - the audit of every `agc_fail` and `agc_fail_text` site in `vm/` (state left half-done, `malloc`'d temporaries live across the jump), and a fuzzer mode that runs the mutant's body in a task.
  - **Front end:** `src/lower.rkt` picks the `Task.await` entry from the checker's type of `R` (17a's `Task.map` items always use the `Result` entry); the `Task.unobserved_crash` catalog entry.
  - **`std/bdd`:** after each handler, check `Task.pending_count()` first, then `Task.unobserved_crash()`, and fail the step with `RUNTIME-TASK-CRASHED` and its text; the runner skips stderr lines with `"task": true` when it reads a child's last diagnostic.
  - **Migrate existing tests** (a crash in a task no longer ends the run):
    - `tests/fixtures/vm/task-preempt-fail.agc`: `main` loops forever after spawning a task that crashes, so it would never end. Bound the loop, then await the task: the run ends with `RUNTIME-TASK-CRASHED` at the await (exit 1), and the crash still shows the task ran while `main` looped.
    - `task-fail-unawaited.agc`: `main` now wakes after its sleep and prints `never`. Shorten the sleep to 10 ms and rename the line; the run exits 1 with the crash line and the summary line on stderr.
    - `task-fail.agc` and `task-sleep-negative.agc`: their task's `R` is `Int` or `Void`, so `main` halts with `RUNTIME-TASK-CRASHED` at its `Task.await`, with the original code in the message and the crash line on stderr.
    - `tests/bdd-test.rkt:113` and `:122`: the "a task crashes" step spawns a crash and sleeps 60 s, which now meets the scenario deadline. Replace `Task.sleep(60000)` with `Task.sleep(0)`, which yields so the crash task runs; the step fails when its handler returns, and line 122 expects `RUNTIME-TASK-CRASHED` with `RUNTIME-DIVISION-BY-ZERO` in the message.
    - `make goldens` for the expected files of the fixtures above. Crash lines on stderr carry the fixture's absolute path, so the golden harness replaces the fixture directory with a fixed token before it compares stderr.
  - **New tests:** §37.11.

  - **Done.** As built:
    - `agc_vm_run` runs each turn under its own `setjmp` (`vm->turn`, used while `vm->in_turn`); a crash in a task other than `main` goes through `crash` in `vm/task.c`, in the order of §37.8. The second await entry is `Task.await_result`, picked by `src/lower.rkt` when the checker's type of the call is a `Result`.
    - Owners: `agc_own` records the task that made a file (`vm/files.c`), a socket or listener (`own` in `vm/tcp.c`) or a process (`vm/process.c`) and its close: an `OP_CLOSE` job with no task (`agc_io_detached`), pending while a job holds the file (`close_pending` in `vm/loop.c` runs it after that job's `done` or `expired`, also for a detached job); `disown`; `close_proc`. A closing handle wakes its lock waiters, and `agc_handle_wait` lets them through to the closed error. Servers have no close yet: `close_server` comes with 20c.
    - The audit found no failure that leaves runtime state half-done: every failure that is not fatal (`RUNTIME-STEP-LIMIT` and `RUNTIME-INTERNAL` end the run) comes before the builtin changes runtime state, or after a finished change (`RUNTIME-PROCESS-CLOSE` after `Process.close` has closed the child). The `malloc`'d temporaries live across a failure only before `RUNTIME-INTERNAL`, which ends the run.
    - **Dropped by the owner:** the fuzzer mode that runs the mutant's body in a task (no new fuzzers).
    - Tests are the migrated ones above, `task-crash-result.agc` (the `Result` entry, `Task.unobserved_crash`, the three stderr formats), `task-crash-descendants.agc`, `tcp-crash-echo.agc` (the `tcp_echo` case: the client of the crashed connection reads `error("network: end of input")`, the listener and the next connection work), the BDD step and a crash before `BDD.run` (a file error), a lowering test of the two await entries, and a `tests/filesystem-test.rkt` case that checks a crashed task's buffered write is on disk after the run; `tests/process-test.rkt` ("every way a run ends") now awaits its crashing task and expects `RUNTIME-TASK-CRASHED`; `vm/tests/task_cancel_test.c` now expects a task that awaits a cancelled task to crash. These cases of §37.11 were left out by the owner's rule (only the tests that prove "Done when"): the separate stderr lines in `--ai` and plain beyond the harness check, a non-`Result` await from another task (that task crashes in turn), two awaits of one crashed task (one parked before the crash), the unobserved crash with `System.exit(0)`, `Task.unobserved_crash` before any crash, a crash in `main`, `RUNTIME-STEP-LIMIT` and `System.exit(3)` in a task, `RUNTIME-STACK-OVERFLOW` in a task, awaiting a cancelled descendant (no program can reach one yet), the handle cases other than the socket (a file another task holds, a struct-nested socket, a file captured by a block, a spawned process, an `HttpClient` used by another task), the C tests (the `next_owner` hand-on, the pending file close with an attached and a detached holder, the subtree cleanup) and the latency case with 10,000 descendants and 1,000 files.
    - **Cost (departs from §37.8):** the cancel of the descendants and the closes are not charged to any turn. `agc_task_cancel` charges the task that calls it, here the crashed task, whose turn has already ended; the descendants were paid for when they were spawned.
    - One rule for every file at the end of the run (owner decision, in the style of Erlang's `halt` flush timeout): the end of the run (`agc_io_flush_files`, called by `end_run` in `vm/main.c`, §10.2.2 "End of run") closes each file still open with the same `OP_CLOSE` job as a crashed task's file (`close_files` in `vm/loop.c`), then waits for all file close jobs (`finish_flushes`, `uv_run` ONCE, no busy wait). The wait has no limit by default (the owner replaced this on 2026-10-13: the limit becomes always on, 30 seconds by default, row 7.2.1d of the roadmap); `agentica --flush-timeout MS` bounds it, and when time runs out the run still ends with the same exit code and prints one stderr line, `agentica: file data may not be written: the flush took longer than MS ms` (`--json`: `{"flush_timeout_ms":MS,"warning":"file data may not be written"}`). A file whose own operation is still in the pool when the run ends gets no close job and is not waited for, as before. `File.close` from another task on a file whose close is pending returns `ok()` at once, as for any closed handle: the flush belongs to the owner's close, and the run waits for it.
    - A task that returns normally gives the handles it still owns to its parent (`agc_give_owned`), so a handle moved to a helper task by `Task.spawn` is closed if the parent crashes after the helper returned (`tcp-crash-delegate.agc`). A timed-out file operation that took the file's state writes the buffer when its job is dropped (`drop` in `vm/files.c`); the write buffer is always empty there today, since a write moves it into the request before the job starts, so this is a guard. Tests: a `tests/filesystem-test.rkt` case for a bad `--flush-timeout` (exit 2) and one where the flush to a FIFO nobody reads times out.

**Done when:** a task that divides by zero gives its awaiter `error("task crashed: ...")` while `main` goes on, an unawaited crash prints its diagnostic and makes the run exit 1, a crash in `examples/tcp_echo.agc`'s `echo` closes only its socket (through the spawn move; after 24b, through the explicit hand-off), and the fixtures and the existing latency test (`make vm-latency`) pass. The latency case of §37.11 was dropped (see "Done").

- [ ] **24b: one handle-ownership rule ([§14.5](../vm/14-core-invariants.md#145-handles)).** A handle belongs to the task that opened it; if that task ends, in any way (return, crash, cancel), without closing it, the handle is closed; handing it to another task is always explicit, through one form. It replaces three mechanisms: 24a's spawn move (a handle passed directly as the `Task.spawn` argument moves to the new task, `builtin_spawn` in `vm/task.c`), 24a's give-back (a task that ends normally gives its handles to its parent, `agc_give_owned` in `vm/loop.c`), and 20c's group registration (`HttpWire.spawn` registers each connection's socket with the server's group, which closes it when the connection task ends or at `close_server`, [§30.6](../future/30-hybrid-http.md#306-server-tasks-close_server-and-task-cancellation)). The group registration becomes one use of the explicit hand-off: `HttpWire.spawn` hands the socket over with it. Its place in the order is row 7.2.1a of the [roadmap](README.md), after HTTP 20c and the VM layers (row 7.2.1b, [§15](../vm/15-layers.md#15-vm-layers), so the hand-off is a port function), so the server's hand-off is known when the one form is chosen. One PR. Decided by the owner on 2026-10-13: ownership decides who closes a handle, not who may use it, so shared use stays as [§37.5](../future/37-task-crash-isolation.md#375-handles-of-a-crashed-task) "Shared handles" says, and `HttpClient` stays exempt.
  - **Spec first:** the one explicit hand-off form (for example a builtin that gives a handle the caller owns to a task it spawned) in §37.5, and `HttpWire.spawn` in §30.6 described as a use of it. Behavior changes: a handle opened in a helper task and returned through `Task.await` is closed when the helper ends unless it is handed over; a cancelled task's handles are closed (today they stay open until the end of the run, `end_cancelled` in `vm/task.c`), which reaches `Test.run`'s leftovers and cancelled handlers, and an `HttpServer` whose owner is cancelled (today it keeps its port bound until the run ends; 20c's `close_server` already closes its own group's handles through `agc_task_drop`); and a server loop that passes a connection to `Task.spawn` must hand it over, or a crash in the connection task leaves its client waiting.
  - **VM:** one close path for every task end (return, crash, cancel) through `agc_close_owned`; `agc_give_owned` and the spawn move are removed; `HttpWire.spawn` uses the explicit hand-off.
  - **Programs:** `examples/tcp_echo.agc` (its `Task.spawn(&echo, connection)`) switches to the explicit form; so does `std/http`'s server through `HttpWire.spawn`.
  - **Docs:** §37.5, §30.6, §10.2.1 "Owners", [§14.5](../vm/14-core-invariants.md#145-handles) (the target becomes as built), `docs/grammar.md`, the programming skill (`references/tasks.md`, `references/network.md`), the site page of `Task`, the development skill.
  - **Tests:** goldens for a handle left open by a task that returns (closed), one handed over explicitly (still open), a cancelled task's handle (closed), and the server's per-request connection; `tcp-crash-echo.agc` and `tcp-crash-delegate.agc`, which rely on the spawn move and `agc_give_owned`, switch to the explicit form.
