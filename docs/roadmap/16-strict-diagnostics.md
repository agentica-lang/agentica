## Phase 16: Strict diagnostics

Specified in [`docs/future/26-strict-diagnostics.md` section 26](../future/26-strict-diagnostics.md#26-strict-diagnostics), with its principle: Agentica has no warnings, so a diagnostic is an error or it does not exist (agents ignore warnings, a warning is a second accepted way, and each stage returns one diagnostic). Every item comes after 7i deletes the evaluator (order 7.2) and lands at order step 7.6, before the phase 15 items of that step (15b to 15e, 15i, 15j), so their new examples and fixtures are written under these rules and 15b's re-exports count as uses from the start. Phase 17's `Task.map` and channels (17a, 17b, order step 7.3), HTTP streaming and `TlsContext` (order step 7.4) land earlier, so each PR here counts and migrates their programs too (§26, "Impact on existing code"). All four are front end only: the linker or the checker, and for 16b's discard `_` a few lines in the parser and `src/lower.rkt`. The bytecode format and the VM do not change. One small PR per item, in the order 16a, 16c, 16b, 16d: the two small migrations first; 16b after 16c, so a read in dead code is already rejected when 16b lands; 16d last, since its one explicit discard, `_ = f(...)`, comes with 16b. Each is a breaking change: its PR migrates every program in the repo that it breaks (`examples/`, `stdlib/`, `benchmarks/`, the `.agc` fixtures, the Agentica programs inline in the Racket tests, the site's `agentica` blocks and the skill's examples; counts in §26, "Impact on existing code") and adds a "Changed" entry to `CHANGELOG.md`. Each PR covers its code with checker or linker tests that assert the code and the span, an `{expect="CODE"}` site example (run end to end by `tests/site-examples-test.rkt`) and one CLI check (`racket src/main.rkt --json check file.agc`: exit 1 and the code); there is no golden fixture, since the VM goldens must compile and a program with a front-end diagnostic does not. Docs (each PR also checks the examples in `grammar.md` and `README.md`, so none shows a form it now rejects): `grammar.md` (and §7 "Diagnostics for agents" gets the no-warnings principle with whichever item lands first, 16a in this order), the programming skill (`references/diagnostics.md` and one line in `SKILL.md`), the site page and the development skill's notes. There is no flag to turn the checks off.

- [ ] 16a `CHECK-UNUSED-IMPORT` (§26.1), in the linker (`src/modules.rkt`), the only stage that sees import aliases: an import whose alias no `Alias.name` of its file resolves through (calls, `&Alias.f`, types, constructions, enum variants and patterns; a re-export of 15b too) is an error at the alias, in every linked file (`std/` and `pkg/` included). `import-decl` gains the alias's span. A file with a call through a name that is not one of its aliases and not a builtin (a mistyped alias, `Txet.shout`) skips the check, so the checker reports `CHECK-UNKNOWN-NAME` at the call instead (test for it). An import alias used without its member, as a one-part type or enum name (`u: User`, a parameter type, `User(name: "Ana")`, `Domain.Some(1)`, or the pattern `Domain.Some(x)`), stops the linker with `CHECK-IMPORT-NAME` and a help that shows the missing member (`User.<Type>`, `Domain.<Enum>.Some(...)`), naming it when the module exports a declaration of that name or exactly one enum with that variant (tests for each shape). The CHANGELOG entry tells package authors that an unused import in a `pkg/` library now fails every user's build. Migration: one test (`tests/modules-test.rkt:207`, whose `types.agc` never uses its alias `B` and expects `CHECK-UNKNOWN-TYPE`: give `B` a use). Docs: `grammar.md` ("File modules and imports"), `references/modules.md`, `site/content/tour/modules.md`.
- [ ] 16b `CHECK-UNUSED-VARIABLE` (§26.2), in the checker: a variable, `for` variable, block parameter or `case` pattern binding that is never read, unless its name starts with `_` (already valid names); function parameters are never reported. This item also makes a bare `_` the discard everywhere it binds a name, as in patterns: `_ = f(...)` (any type, any number of times; an annotation is `PARSE-UNEXPECTED-TOKEN`), `for _ in`, `|_, v|`; reading `_` is `CHECK-UNKNOWN-NAME` with a help. A small grammar change (the meaning of `_`; the EBNF is the same); the scan found nothing that breaks (three `for _ in` loops stay valid). A read inside the value of an assignment to the same variable (`x += 1`, `xs = xs.push(v)`) does not count; reassignment before a read is not reported (no flow analysis); a read in a block counts for the captured variable. Reported at the end of each function, after its `CHECK-MISSING-RETURN` checks, at the name whose span starts first. The help depends on the type: for a `Result`, the 16d handling forms or `_ = f(...)`, never a bare call statement. `for-stmt` gains a `var-span` and `variant-pattern` gains `binding-spans`. Migration: the largest (about 30 program and test files, and 17 site blocks on 7 pages). Docs: `grammar.md` ("Variables and scope" with the discard `_`, "Statements and blocks", patterns, blocks, and the `xs = xs.push(2)` example of "Methods on builtin types"), `SKILL.md`, `site/content/tour/variables.md`, `control-flow.md`, `blocks.md`, `enums-and-case.md`.
- [ ] 16c `CHECK-UNREACHABLE-CODE` (§26.3), in the checker: a statement after `return`, `break` or `next`, or after an `if`/`else` or `case` whose every branch ends in one, is an error at the first such statement, with a secondary span on the terminator. It is separate from `CHECK-UNREACHABLE-CASE-ARM`, which does not change. `System.exit`, `!` calls, `while true` and `try` are not terminators, as for `CHECK-MISSING-RETURN`. Migration: one fixture (`tests/fixtures/vm/calls.agc`). Docs: `grammar.md` ("Statements and blocks", "Functions and entry point"), `SKILL.md`, `site/content/tour/control-flow.md` and `functions.md`.
- [ ] 16d `CHECK-UNUSED-RESULT` (§26.4), in the checker (`check-unused-value!`): a dropped value (an expression statement, or the last statement of a `Void` block) whose type is `Result[...]` is an error, whoever made it (a builtin with effects, a user function, a method, `Task.await`), except `IO.inspect`, which prints and returns its argument. The help shows `try`, a `case` on `ok(_)`/`error(message)`, `.unwrap!`, or the one explicit discard, `_ = f(...)` (from 16b), never a named `_written = ...`. `CHECK-UNUSED-VALUE` stays; it runs after this check, so it never sees a `Result` and its help never suggests `_ =`. `try f(...)` as a statement stays valid (its value is the payload). Migration: 12 statements (2 examples, 4 file fixtures, 1 inline checker test). Docs: `grammar.md` ("Result and propagation", "Methods on builtin types"), `SKILL.md`, `references/diagnostics.md`, `site/content/tour/results-and-try.md` and the library pages that drop a `Result`.

**Done when:** the four codes are in `grammar.md`, the programming skill and the site; `make test` passes with every program in the repo migrated; and none of the codes can be turned off.
