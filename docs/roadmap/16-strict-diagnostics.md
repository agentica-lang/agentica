## Phase 16: Strict diagnostics

Specified in [`docs/future/26-strict-diagnostics.md` section 26](../future/26-strict-diagnostics.md#26-strict-diagnostics), with its principle: Agentica has no warnings, so a diagnostic is an error or it does not exist (agents ignore warnings, a warning is a second accepted way, and each stage returns one diagnostic). Every item comes after 7i deletes the evaluator (order 7.2) and lands at order step 7.4, before the phase 15 items of that step (15b to 15e, 15i, 15j), so their new examples and fixtures are written under these rules and 15b's re-exports count as uses from the start. All three are front end only (the linker or the checker); `src/lower.rkt`, the bytecode format and the VM do not change. One small PR per item; the items are independent. Each is a breaking change: its PR migrates every program in the repo that it breaks (`examples/`, `stdlib/`, `benchmarks/`, the `.agc` fixtures, the Agentica programs inline in the Racket tests, the site's `agentica` blocks and the skill's examples; counts in §26, "Impact on existing code") and adds a "Changed" entry to `CHANGELOG.md`. Each PR has checker or linker tests that assert the code and the span, a golden fixture, an `{expect="CODE"}` site example, and docs: `grammar.md`, the programming skill (`references/diagnostics.md` and one line in `SKILL.md`), the site page and the development skill's notes. There is no flag to turn the checks off.

- [ ] 16a `CHECK-UNUSED-IMPORT` (§26.1), in the linker (`src/modules.rkt`), the only stage that sees import aliases: an import whose alias no `Alias.name` of its file resolves through (calls, `&Alias.f`, types, constructions, enum variants and patterns; a re-export of 15b too) is an error at the alias, in every linked file (`std/` and `pkg/` included). `import-decl` gains the alias's span. Migration: one fixture (`tests/fixtures/vm/linked.agc`). Docs: `grammar.md` ("File modules and imports", and §7 gets the no-warnings principle), `references/modules.md`, `site/content/tour/modules.md`.
- [ ] 16b `CHECK-UNUSED-VARIABLE` (§26.2), in the checker: a variable, `for` variable, block parameter or `case` pattern binding that is never read, unless its name starts with `_` (already valid names, no grammar change); function parameters are never reported. A read inside the value of an assignment to the same variable (`x += 1`, `xs = xs.push(v)`) does not count; reassignment before a read is not reported (no flow analysis); a read in a block counts for the captured variable. Reported at the end of each function, at the first such name in the source. `for-stmt` gains a `var-span` and `variant-pattern` gains `binding-spans`. Migration: the largest (about 30 program and test files, and 16 site blocks on 7 pages). Docs: `grammar.md` ("Variables and scope", patterns, blocks), `SKILL.md`, `site/content/tour/variables.md`, `control-flow.md`, `blocks.md`, `enums-and-case.md`.
- [ ] 16c `CHECK-UNREACHABLE-CODE` (§26.3), in the checker: a statement after `return`, `break` or `next`, or after an `if`/`else` or `case` whose every branch ends in one, is an error at the first such statement, with a secondary span on the terminator. `System.exit`, `!` calls, `while true` and `try` are not terminators, as for `CHECK-MISSING-RETURN`. Migration: one fixture (`tests/fixtures/vm/calls.agc`). Docs: `grammar.md` ("Statements and blocks", "Functions and entry point"), `SKILL.md`, `site/content/tour/control-flow.md` and `functions.md`.

**Done when:** the three codes are in `grammar.md`, the programming skill and the site; `make test` passes with every program in the repo migrated; and none of the codes can be turned off.
