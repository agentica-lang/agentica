## Phase 25: Unit tests

Specified in [`docs/future/36-unit-tests.md` section 36](../future/36-unit-tests.md#36-unit-tests-test). Phase 25 adds the builtin `Test` module and runs `*_test.agc` files with `agentica test`, next to the features, through the BDD runner and report. It comes right after task crash isolation (phase 24), so a crash fails one test; its place in the order is row 7.1 of the [roadmap](README.md). It has two PRs, each with its own tests and docs.

- [x] **25a: the `Test` module (§36.3, §36.4).**
  - **VM:** `Test.test` (the `TestCase` value with its call span; as built, an opaque type, not a record), `Test.eq` (it pulls §25.4's type predicate and deep compare forward, with an explicit stack, for 15d to reuse; `Json` at any depth compares and prints as canonical text), `Test.ok?`, `Test.error?`, `Test.assert`, the assertion records on the nearest test task, and `Test.run` (list and run modes, one task per test, the pending-task and unobserved-crash checks, the records of §36.6 with raw texts, the per-test seed from the given seed and the test name).
  - **Front end:** the catalog entries; `Test.eq` needs a type with §25.4 equality or `Json` (`CHECK-TYPE-MISMATCH`); `Test` and `TestCase` reserved.
  - **Tests:** the golden fixtures and checker tests of §36.12.
  - **Docs:** `docs/grammar.md` (the `Test` module, reserved names); the programming skill (`references/testing.md`, its row in "When to read a reference", `references/diagnostics.md`); `site/content/library/test.md`; the development skill.
  - **Done.** As built:
    - `vm/testing.c` holds the `Test` builtins; `vm/equal.c` holds `agc_equal`, the deep compare (one explicit stack of value pairs, Floats by IEEE 754, maps by key in any order, a `Json` by its canonical `JSON.encode` text, `RUNTIME-INTERNAL` for a value with no equality); `agc_test_text` in `vm/text.c` is the inspect form with each `Json` as its canonical text. Both are in `vm/agc.h` for `std/bdd` (25b) and `==` (15d) to reuse; BDD is not wired to them yet.
    - `TestCase` is an opaque builtin type, like `FileHandle` (a new value tag, `<TestCase>` in inspect), not a builtin record: it has no fields at all, so a record gave nothing.
    - Each task records the test it was spawned under (`test`, inherited at spawn; a test's task points to itself). An assertion records its first failure there (`note`), which is the nearest test task of §36.3 without walking parent links. When a test's task ends, the scheduler records whether it left running children (`left_children`): that is the pending check, made when the test returns, not when `Test.run` wakes later. Its leftover tasks, which moved to the caller of `Test.run`, are cancelled with `agc_task_cancel` whatever the outcome. The unobserved-crash check looks only at crashes of tasks spawned under that test, and after the record every crash of that test's tasks is observed, so a second crash or a leftover's crash never reaches the next test. At the end of stdin and after a list, `Test.run` ends the run as a return from `main` does (`agc_report_unobserved`): a crash outside every test that nothing observed prints the summary line and exits 1, which the 25b runner reports as a file error. `Test.run` inside a test, or while another one serves the runner, is the new code `RUNTIME-TEST-RUN`.
    - The outcome order is §36.3's (crash, first assertion, the block's `error`), then pending tasks, then an unobserved crash. A crash keeps its code, message and span on the task (`crash_code`, `crash_message`, `crash_span`) for the record.
    - Records use the BDD marker (U+001E and `agentica-bdd `) and sorted keys. A `fail` record is the `--json` diagnostic (`code`, `file`, `message`, `range`) plus `event`, `expected` and `actual`. An index line that is not plain digits (no sign, no leading zero) naming a test is a `RUNTIME-BDD-INFRA` fail record and exit 1. `Test.run` checks the names before it looks at the mode, so a bad name fails a direct run too.
    - The per-test seed is the run's seed (`--seed`, or the one drawn at start, now kept in the runtime) XOR the FNV-1a hash of the name, through the usual splitmix64 seeding.
    - The checker's predicate for `Test.eq` is `data-type?` (the old `printable-type?`, renamed): the §25.4 set plus `Json`. 15d needs it without `Json`. The §25.4 message that names the field without equality, with its secondary span, is left for 15d.
    - The assertions carry the effect `test` in the catalog, so an assertion used as a statement is not `CHECK-UNUSED-VALUE`.
    - Tests: the goldens `test-assertions` (run mode: every assertion passing and failing, a struct, a map in another key order, an enum, a Result, `Json` and a list of `Json`, an ignored failure, the block's error, a crash and the next test, pending tasks, an unobserved crash, an assertion in a spawned task at that task's span, `Test.run` inside a test, an assertion outside a test), `test-crash-observed` (two crashes in one test, a leftover that crashes after its test returned, and a crash outside the tests that only the end-of-run summary reports), `test-list` (list mode), `test-direct` (run directly: stderr, exit 2), `test-name-empty` and `test-name-duplicate`; a seed check in `tests/vm-diff-common.rkt` (a test gives the same values alone and after another test, and other values with another seed) and the span of `RUNTIME-TEST-NAME` at the second `Test.test` call; checker tests for two different types, an `Fn`, a struct with an `Fn` field, a block that does not return `Result[Void]`, `try` in a test block, and `Test` and `TestCase` as type names.
    - **Left for 25b:** the CLI tests of §36.12 and `RUNTIME-TEST-TIMEOUT` (the runner's deadline).
    - **Dropped by the owner's rule** (only what proves the change): a deep value for the explicit stack and a C test of `agc_equal` (15d adds them with `==`).
- [ ] **25b: `agentica test` runs test files (§36.5 to §36.8).**
  - **Driver** (`src/bdd-driver.rkt`): find `*_test.agc` next to `.feature` files in one pass; the default paths `specs/` and `test/`; compile each test file; `--only TEXT`.
  - **Runner and report** (`stdlib/bdd/runner.agc`, `stdlib/bdd/report.agc`): the list and run children for test files (with `--allow-run`), the seed drawn when none is given, the 30-second deadline per test from the moment its index is sent, the output limit and captured stdout per test, the list record's `line` and `column`, `kind`, `output`, `seed`, the `not_executed` status and count.
  - **First users:** unit tests for `std/queue` and `std/http`'s pure helpers in `tests/std/`, run by a rackunit test.
  - **Tests:** the CLI tests of §36.12.
  - **Docs:** `docs/grammar.md` and `docs/bdd.md` (`agentica test`), the programming skill (`references/testing.md`, `references/bdd.md`), `site/content/getting-started.md`, the development skill.
  - No CHANGELOG: the project adds none in the private alpha.

**Done when:** `agentica test test/` runs a `*_test.agc` file and a `.feature` file in one report with the BDD formats and exit codes, a failed `Test.eq` shows expected, actual and its span, a crashing test fails alone, and the `std/` unit tests run in `make test`.
