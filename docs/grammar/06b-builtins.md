### Methods on builtin types

`receiver.name(args)` calls a builtin whose first parameter has the receiver's type. The checker picks the module from the static type (`String`, `List`, `Map`, `Set`, `Float`, `Result`, `Range`, `Int`, and `Json` through `JSON`); there is no dynamic dispatch. `s.trim` is `String.trim(s)`, but `"a".from_int` is not a method. Without parentheses, `receiver.name` on a non-struct value is a method without arguments (`s.length`, `r.ok?`). On a struct, `.name` is a field. Structs and enums have no methods.

Ruby aliases are the module functions named in the library pages: `size`, `length`, `strip`, `include?`, `start_with?`, `end_with?`, `push`, `join`, `to_f`, and `to_s` and `inspect` on any data value. Two differ from Ruby: `to_i` and `to_f` on text return a `Result` (`"abc".to_i` is an error, not `0`), and `to_i!` and `to_f!` halt on bad text. An unknown method is `CHECK-UNKNOWN-METHOD`.

`x.to_s` is the text `"#{x}"` gives: a `String` as is, a `Json` as its JSON text, and any other data value in its `inspect` form (`[1, 2]`, `ok(3)`, `Item(name: "a")`). Inside a list, a `Json` shows as `<Json>`. Functions, tasks and handles have no `to_s`, so printing or interpolating one is `CHECK-TYPE-MISMATCH`. Unlike Ruby, `nil.to_s` is `"nil"`. `x.inspect` keeps a string's quotes; it is for display, not valid source.

Values are immutable: a method never changes its receiver, so `xs.push(2)` returns a new list. A builtin without effects whose non-Void result is dropped is `CHECK-UNUSED-VALUE`; write `xs = xs.push(2)`. Builtins with effects, functions ending in `!`, and builtins that take a function are exempt. A negative literal receiver needs parentheses: `(-5).to_s`.

### Minimal builtin functions

`puts(value)` writes the value's `to_s` and a newline; `print` writes without one. `gets` and `gets!` are `IO.gets` and `IO.gets!`, and may drop their parentheses (`line = gets!.strip`). `Map`, `Set` and `List` are builtin modules whose generic functions the checker treats specially. Signatures are in [`library/data-structures/list.md`](../../site/content/library/data-structures/list.md), [`library/data-structures/map.md`](../../site/content/library/data-structures/map.md) and [`library/data-structures/set.md`](../../site/content/library/data-structures/set.md).

Callbacks (`List.map`, `filter`, `reduce`, `each`, `any?`, `all?`, `sort_by`, and the Enumerable methods below) take a block, `&name` or a function variable. Each runs once per element, left to right, under the caller's budget. Parameter and return types must match exactly, and a `map` callback returns data, not Void. Annotated block parameters let an empty list or an empty `reduce` initial value infer its type. `List.any?` and `List.all?` stop at the first deciding element.

Collection operations preserve their inputs. Costs exclude callback work.

- `List.map` and `List.filter` are O(n). `List.reduce` folds left, calling `f(accumulator, item)`; an empty list gives the initial value.
- `List.append` (`push`) takes near constant time, so building a list with n appends is O(n). `List.concat` joins lists of one element type: O(b) when the right list has at most 32 items, otherwise O(a + b). `List.reverse` is O(n).
- `List.set` and `List.at` are zero-based and take O(log32 n) time (at most four steps for a million items). A negative or out-of-range index is `RUNTIME-INDEX-OUT-OF-RANGE` at the index argument.
- `List.repeat` takes a count from 0 to 1048576; zero gives an empty list of the element type. Other counts are `RUNTIME-INVALID-COUNT`.
- `List.take` and `List.drop` need a nonnegative count (`RUNTIME-INVALID-COUNT`). A larger count gives the whole list or an empty list. They are O(n) in the size of the result.
- `List.sort` and `List.sort_by` sort ascending. Elements, or the keys from `sort_by` (computed once per element, left to right), must be `Int`, `Float` or `String`; otherwise `CHECK-TYPE-MISMATCH`. The sort is stable. Strings compare by code point, so `"B"` is before `"a"`. NaN goes last. O(n log n), plus key calls.
- `List.find` gives `ok(element)` for the first element the block accepts, or `error("not found")`, and stops calling the block there. `List.each_with_index` calls `f(element, index)` with the index from 0 and gives nothing back. `List.flat_map` joins the lists the block returns, in order. `List.partition` gives `[accepted, rejected]`. `List.take_while` and `List.drop_while` call the block until it first returns false, and not after. All are O(n).
- `List.each_slice(n)` gives the slices of `n` elements as a `List[List[T]]`, the last one shorter. It has no block form: a block after it is `CHECK-BLOCK-TARGET`, and `xs.each_slice(2).each do |pair| ... end` walks the slices. An `n` below 1 is `RUNTIME-INVALID-COUNT` at the argument.
- `List.group_by` (the key is an `Int` or a `String`; other types are `CHECK-TYPE-MISMATCH` at the block) gives a `Map[K, List[T]]` whose keys and elements keep the order of first appearance. `List.tally` counts equal `Int` or `String` items in a `Map[K, Int]` in the same order. `List.uniq` keeps the first of each `Int` or `String` item. O(n).
- `List.sum` adds a `List[Int]` or `List[Float]` from the left; an empty list gives `0` or `0.0`, and an `Int` overflow is `RUNTIME-INTEGER-OVERFLOW` at the call. Other item types are `CHECK-TYPE-MISMATCH`.
- `List.min_by` and `List.max_by` call the key block once for each element, from the first to the last, and give `ok(element)` for the least or greatest key, or `error("the list is empty")`. The key is an `Int`, a `Float` or a `String`. The first element wins a tie. A NaN key never wins unless every key is NaN, and then the first element wins. `String` keys compare with `String.compare`.
- `Map.each` calls `f(key, value)` for each entry in insertion order and gives nothing back. `Map.filter` keeps the entries `f(key, value)` accepts, in insertion order. Both are O(n).
- `String.compare(a, b)` (also `a.compare(b)`) gives `-1`, `0` or `1` in the order of `sort`: code point order, which is the byte order of UTF-8.
- These methods are written in Agentica in `stdlib/prelude/` and run in the program: they use its step budget, and a runtime error in one is reported at the call in the program (at the argument it names), never in the prelude. They have one name each: `select`, `collect`, `detect`, `inject` and `reject` are `CHECK-UNKNOWN-METHOD`, and so are the same names on a `Range`.
- `Map.get` with two arguments gives `ok(value)` or `error(message)`. With three, the default is always evaluated; `false` and `nil` are present values.
- `Map.delete` ignores absent keys and keeps the order of the rest; a key put back later goes to the end. It is O(n). `Map.values` follows the `Map.keys` order.
- `Set.new` keeps the first of repeated items. `Set.add` of a member and `Set.delete` of a missing element give the same set. `Set.delete` is O(n) like `Map.delete`; `Set.include?` and `Set.add` take effectively constant time.

Expected types flow into these operations for empty collections and Results.

- `String.length` and `String.slice` count characters, not bytes. An out-of-range `slice` is a runtime error.
- `String.split(s, sep)` keeps empty parts, so `String.join(String.split(s, sep), sep)` gives `s`. `String.split("", sep)` is `[""]`; `String.split(s, "")` gives one character per element.
- `String.to_int!` accepts a signed decimal: `RUNTIME-INVALID-NUMBER` for other text, `RUNTIME-INTEGER-OVERFLOW` outside `Int`. `String.to_float!` rejects text that is not a real decimal with `RUNTIME-INVALID-NUMBER`.
- `String.index_of` gives the character index of the first match (`ok(0)` for an empty part), or an error when absent. `String.at` halts with `RUNTIME-INDEX-OUT-OF-RANGE` outside the string.
- `String.code` and `String.from_code` halt with `RUNTIME-INVALID-CHARACTER` on other input: a one-character string, or a scalar value (0 to 0x10FFFF, no surrogates).
- `Float.to_int` truncates toward zero; NaN, infinity and results outside `Int` are errors. `Float.to_int!` halts instead, with `RUNTIME-INVALID-NUMBER` or `RUNTIME-INTEGER-OVERFLOW`.
- `Int.bit_and`, `bit_or`, `bit_xor`, `bit_not`, `shift_left`, `shift_right` and `shift_right_unsigned` work on the 64-bit two's complement form of their arguments and read the result back the same way. They are methods on `Int` (`flags.bit_and(4)`, `x.shift_left(8)`) with no effects, so an ignored result is `CHECK-UNUSED-VALUE`. The core has no hex literals, so masks are written in decimal. `bit_and`, `bit_or`, `bit_xor` and `bit_not` never fail; `bit_not(a)` is `-1 - a`.
- `Int.shift_left(a, n)` is the low 64 bits of `a * 2^n`: bits that leave the top are dropped and bit 63 becomes the sign, so `1.shift_left(63)` is `-9223372036854775808` and the shift wraps where `*` halts with `RUNTIME-INTEGER-OVERFLOW`. `shift_right` is arithmetic (copies of the sign bit come in) and rounds toward minus infinity, so `(-7).shift_right(1)` is `-4`. `shift_right_unsigned` is logical (zeros come in), so `(-1).shift_right_unsigned(60)` is `15`. A count of 64 or more shifts every bit out: `shift_left` and `shift_right_unsigned` give `0`, and `shift_right` gives `0` for `a >= 0` and `-1` for `a < 0`. A negative count is `RUNTIME-INVALID-COUNT` at the count argument.
- `Float.to_bits(x)` gives the IEEE 754 binary64 bits of `x` as a two's complement `Int` (`1.0` is `4607182418800017408`, `-0.0` is `-9223372036854775808`). Every NaN gives the quiet NaN `9221120237041090560`. `Float.from_bits(n)` reads the 64 bits of any `Int` as a binary64; subnormals, infinities and `-0.0` come back exactly and any NaN pattern gives NaN, so `Float.to_bits(Float.from_bits(n)) == n` except for NaN patterns other than the quiet NaN.
- `Float.to_bits32(x)` rounds `x` to binary32 (to nearest, ties to even) and gives its 32 bits as an `Int` from `0` to `4294967295`. A magnitude of `2^128 - 2^103` or more becomes infinity with the same sign, small magnitudes round to a subnormal or to zero and keep their sign, and every NaN gives `2143289344`. `Float.from_bits32(n)` widens a binary32 to a `Float` exactly; an `n` outside `0 .. 4294967295` is `RUNTIME-INVALID-NUMBER` at the argument. `Float.to_bits32(Float.from_bits32(n)) == n` except for NaN patterns other than `2143289344`.

- `IO.gets` gives `ok(line)` without its terminator (LF, CR or CRLF), or an error at EOF; a blank line is `ok("")`. `IO.gets!` halts with `RUNTIME-END-OF-INPUT` at EOF. `IO.read()` drains stdin to EOF, so it cannot read one message from a peer that keeps stdin open.
- `IO.read_bytes(count)` waits for exactly `count` bytes or EOF, and gives integers 0 to 255 with no decoding. Counts are 0 to 1048576; zero gives `ok([])` without consuming input. `String.from_bytes` decodes strictly as UTF-8: invalid, overlong, surrogate and incomplete sequences are errors, never replacement characters.
- `IO.eof?()` peeks without consuming and can block until data or EOF arrives. Reads have no timeout, and the step budget cannot interrupt blocking I/O.
- `IO.flush()` flushes stdout only. On Linux, a print copies its text into a 64 KiB buffer of the stream and waits in order for room when the buffer is full, without stopping other tasks; a print has no timeout. The loop writes the buffer as the reader takes it, so a print reaches a pipe or file without `IO.flush()`; `IO.flush()` returns when the buffer is empty, that is, when the data is in the pipe or file, and it can wait for a slow reader. When stdout and stderr are the same terminal or file, their output keeps the order of the calls; otherwise there is no order between them. On other systems, output functions do not flush by themselves. A stdio protocol writes one compact JSON message per line, flushes after each reply, and sends logs to `IO.warn` (stderr).
- `Time.now_ms()` is wall-clock milliseconds since the Unix epoch, and can jump; `Time.monotonic_ms()` never goes backward; `Time.monotonic_ns()` is the same clock in nanoseconds, for short durations. `Random.int(min, max)` is uniform over `min .. max`, both included; `min > max` halts with `RUNTIME-INVALID-RANGE`. `Random.float()` is in `0.0` up to, not including, `1.0`.
- `System.env(name)` reads one environment variable of the process: `ok(value)`, with `ok("")` for a variable set to the empty string, and `error(message)` for one that is not set. A name that is empty or contains `=` or NUL is an error too, not a halt. A value that is not valid UTF-8 is not an error: each byte that is not part of a valid UTF-8 sequence becomes U+FFFD, as in `Dir.list` names. The VM hides the variables it keeps for itself, `AGENTICA_CHANNEL` and a `UV_USE_IO_URING` that it set itself; a child started with `Process.spawn` does not get them either. No flag is needed, as for files: the permissions of the host user apply. The home directory is `System.env("HOME")`. There is no call that lists the variables. A child started with `Process.spawn` also does not get `AGENTICA_VM_METRICS` or `AGENTICA_VM_METRICS_FILE` (reserved for the VM's own metrics, a later phase), though `System.env` shows them to the program.
- `System.pid()` is the process id of the running program, an `Int`. It needs no flag. A program that starts a VM with `--driver-pid` passes it, because the child VM checks it against its parent.
- `FrontEnd.hand_off(program, options, arguments)` and `FrontEnd.std_source(path)` belong to the front end of the single `agentica` binary: the first hands a compiled program (a `List[Int]` of bytes) to the VM, which runs it in a new runtime with the given VM options and arguments, and the second reads an embedded `std/` source by its path in `stdlib/`. They are not for programs: they need no flag, but any program that calls them, and any front end run by `agentica run`, halts with `RUNTIME-FRONT-END-ONLY`.
- Each run has one generator, seeded from the operating system unless `agentica --seed N program.agc` is given (N in `0 .. 2147483647`, otherwise exit 2). Each task has its own generator: the main task starts from the seed, and each spawn takes one draw from its parent. Timers and I/O can still change how tasks interleave, so a multi-task run as a whole is not repeatable. The generator is not for secrets.

### JSON

`Json` and `JSON` are reserved. A `Json` value has no constructor, equality, fields or indexing. `IO.inspect` prints `<Json>`; `to_s`, interpolation, `puts` and `JSON.encode` give its text. Signatures are in [`library/text-and-data/json.md`](../../site/content/library/text-and-data/json.md).

- `JSON.object` takes `Map[String, Json]`, `JSON.array` takes `List[Json]`, and `JSON.from` takes any encodable value. A non-finite Float halts with `RUNTIME-JSON-ENCODE`. Null and `false` stay distinct, and so do empty objects and empty arrays.
- `JSON.schema(T)` takes a named struct, as `decode` does, and returns an object schema with `properties` and `required`. Int bounds are signed 64-bit; lists use `items`; String-keyed maps use `additionalProperties`; nested and recursive structs use `$defs` and `$ref`. Extra keys stay allowed.
- `JSON.decode(text, T)` takes a named struct type, not a value; bare type names are valid only for `decode` and `schema`. Fields may be Int, Float, Bool, String, lists, String-keyed maps, and nested or recursive structs; other nested types are `CHECK-NOT-DECODABLE`. Malformed JSON, missing fields, wrong types, Int overflow and non-finite numbers give errors with a field or index path. Extra keys are ignored. A JSON integer may decode as a Float; a decimal or exponent never decodes as an Int. Decoded maps are in sorted key order.
- `JSON.parse` reads exactly one value, with optional surrounding whitespace (space, tab, CR, LF). Empty input, trailing content, invalid escapes, raw control characters and non-finite numbers are errors. A repeated object key keeps its last value.
- `JSON.get` needs an object and a present key; `JSON.at` needs an array and an index in range. Missing keys, bad indexes and wrong kinds are errors. JSON `false` and `null` are present values.
- The extractors (`JSON.string`, `bool`, `int`, `float`, `list`) need the exact kind. `JSON.int` needs an integer within 64-bit bounds, so `1.0` is not an Int. `JSON.float` rounds to a finite binary64, and overflow is an error. Parsed integers may exceed `Int` until extracted. JSON `null` stays a `Json`.
- `JSON.encode` accepts Int, Float, Bool, String, Nil (as `null`), Json, lists, String-keyed maps and structs of those. Results and Int-keyed maps are `CHECK-NOT-ENCODABLE`. Untyped empty containers need an annotation. A non-finite Float halts with `RUNTIME-JSON-ENCODE`; it is never written as null.
- Encoding is compact: struct fields in declaration order, map entries in insertion order. A parsed object encodes its keys sorted by UTF-8 bytes, so `JSON.encode(JSON.parse(x))` is canonical: texts that differ only in whitespace, key order or repeated keys give the same text. `1` and `1.0` stay different.

### Builtin discovery and execution budget

`agentica help NAME --json` prints the name, arity, parameter types, result, signature, effects and description, from the catalog that checking and execution use. Effects are informational (I/O, tasks, or `test`). An unknown target exits 2.

`agentica --max-steps N program.agc` limits a run to N expression or statement entries across all tasks; N must be a positive integer. Runs are unlimited by default, and checking never spends the budget. Exhaustion is `RUNTIME-STEP-LIMIT` at the next node. It is not a wall-clock or blocking-I/O timeout.

At the end of a run the VM waits for the buffered writes of every open file, and for the output of stdout and stderr that a pipe has not taken yet. The wait is always bounded: 30000 milliseconds by default. `agentica --flush-timeout MS program.agc` or the environment variable `AGENTICA_FLUSH_TIMEOUT_MS` sets it (an integer from 0 to 86400000; the flag wins, a bad value exits 2, and there is no way to turn the limit off). On timeout, the run ends with the same exit code, and stderr gets `agentica: file data may not be written: the flush took longer than MS ms` (with `--json`, `{"flush_timeout_ms": MS, "warning": "file data may not be written"}`).

Calls nest at most 10000 deep in each task; a deeper call is `RUNTIME-STACK-OVERFLOW` at the call. A tail call (`return f(...)` to a user function) replaces the caller's frame and does not count, so deep tail recursion runs. A call inside a larger expression, such as `return 1 + f(n - 1)`, and a call of a builtin are not tail calls.

### Running a compiled program

`agentica compile file.agc -o file.agcb` writes a program as bytecode, and `agentica run [OPTIONS] [--] file.agcb [ARGS...]` runs it on the VM with no front end: nothing is read, checked or compiled. `run` must be the first word after `agentica`; after an option it is taken as a source file name and the front end answers with a usage error (exit 2). The options are `--max-steps N`, `--seed N`, `--flush-timeout MS`, `--allow-run`, `--source-root DIR` (the folder put before the file names that the bytecode stores, except the `std/` modules), `--ai` and `--json`, each at most once and with the values and limits they have for `agentica FILE.agc`; `--version` prints the Agentica version and the versions of the libraries the VM links. The words after the file are the program's arguments, even when they look like options. The loader treats the file as untrusted. A file that is not valid bytecode, or whose format or Agentica version is not the binary's, is refused before anything runs; a source file also gets the hint to run it as `agentica FILE.agc`. The exit status is the program's own: `System.exit(n)`, 1 for a diagnostic, and 2 for a command line or a start that fails (a bad option, an unreadable file, bad bytecode), with a message that starts `agentica run:`. The old `agentica-vm` command and the `AGENTICA_VM` variable are gone: nothing reads the variable.
