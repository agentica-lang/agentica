# Pipeline stages reference

Detailed tables for the Agentica front end in `compiler/`. Read this when adding or renaming a token, AST node, or diagnostic code. Each stage has a module and an entry program that prints its text form (`lex.agc`, `parse.agc`, `link.agc`, `check.agc`, `lower.agc`, `bytecode.agc`); the goldens in `tests/fixtures/frontend/<stage>/` pin those texts (`references/frontend.md`).

## Conventions

- A span end is exclusive; offsets count characters (code points); line and column are 1-based.
- Every stage takes the previous stage's data and returns the next data or one diagnostic (`Outcome[T]` or `Result[T]` with a packed diagnostic), stops at the first error, and never prints. A failed internal assumption is a `*-INTERNAL` diagnostic, never a crash.
- The diagnostic forms (`compiler/diagnostic_plain.agc`, `diagnostic_ai.agc`, `diagnostic_json.agc`) render a located header, message, source marks/labels, and grounded help from the same data; `vm/diag.c` prints the same forms for runtime errors.

## Source and tokens

`compiler/source.agc` holds `Position` (offset, line, column) and `Span` (source, start, end). `compiler/token.agc` holds `Token` (kind string, lexeme, `Value`, span); `Value` is the decoded literal (`Text`, `Whole`, `Huge`, `Real`) or `NoValue`, or a `DocBlock` for a `DOC` token: `text` is the doc lines with the `##` markers and one optional space removed, joined by newlines; `next` says what the line after the block is: `blank`, `comment`, `eof` or `code`. The lexer works this out because the `NL` tokens of a blank line and of a `#` comment line look the same.

## Lexer (`compiler/lexer.agc`)

`lex: String -> Outcome[List[Token]]`. One pass over the source:

- CRLF normalizes to one newline; a lone carriage return is `LEX-UNEXPECTED-CHAR`.
- `NL` is suppressed inside `()`, `[]`, and `{}`; each LF/CRLF outside them emits one NL, including blank/comment lines.
- A final `NL` is synthesized before `EOF` when the file does not end with one.
- `#` starts a comment that runs to the end of the line.
- A line whose first non-blank characters are `##` starts a doc block (`compiler/lexer.agc` looks back over blanks to the line break): the lexer reads the consecutive doc lines into one `DOC` token, with the text after `##` and one optional space (`###` keeps its third `#` in the text). A `##` after code on the line is a plain comment. A bare carriage return after a doc line is still `LEX-UNEXPECTED-CHAR`, found by the main loop. The token is emitted inside brackets too; the parser rejects it there.
- A lowercase name may end in `?` or `!` regardless of whitespace before `(`; `!` followed by `=` stays an operator, so `a!=b` is still `a != b`. The parser rejects suffixes on bindings, parameters, and fields. `try` is a keyword.
- Number literals read digits and `_` in both parts (`1_000.000_5`), drop the `_`s for the value and keep them in the lexeme. `LEX-INVALID-NUMBER` (a trailing `_`, a `__`, or a `_` next to the dot) spans the literal as written. A `.` followed by a digit or `_` continues the number; a letter or another `.` ends it (`1_000.times`, `1_000..2_000`). The text conversions (`String.to_int`, JSON) stay strict and reject `_`.
- A heredoc `<<~NAME` (25.10) is the `CharClass.Less` arm of the main loop (`<` has a class of its own, so the operator arm stays short). `scan_heredoc` reads the body lines from the line after the opener (or from the `Resume` that an earlier heredoc of the same line left), takes the common indentation off, and emits the string tokens at the place of the opener, all with the span of `<<~NAME`. Each `#{...}` is lexed by `lex_from`, the main loop itself, started inside the line with the `#` frame pushed and `stop_depth` set to the frame count, so the `}` that finds that depth ends the run; its tokens keep their real positions. The main loop keeps a `resume` point: at the line break of the opener line it emits the `NL` and jumps over the bodies. No field on the token or the node says that a string is a heredoc: its lexeme is the opener (`<<~NAME`), which `Base.heredoc?` reads for the `case` pattern and the `import` path (`PARSE-UNEXPECTED-TOKEN`). Spans inside a body lie after the spans of the nodes that hold them.

## Syntax tree (`compiler/ast.agc`)

Every node is a struct with `span` as the last field and an `id` that is dense across the files of a program. `Program` holds the declarations, `docs` (a map from the span of each documented node to its doc text) and the module doc. The key is the span of the node as it stands in its list: the `ExportDecl` for an exported declaration (not the `def` inside), the `FieldDecl` in a struct, the `EnumVariant` in an enum. The other nodes do not know about docs, so the checker, lowering and bytecode see the tree as before.

| Group | Nodes |
| --- | --- |
| declarations | `Program`, `ImportDecl` (path, alias, `names`: a list of `ImportName` (name, local, span, local span), empty for an alias; exactly one of alias and names is set), `ExportDecl`, `ConstDecl` (name, optional type, value, `exported`, span; `exported` is true for `export NAME = ...`, and the linker clears it), `FunctionDecl`, `Param` (name, type, `default`: an optional expression, span), `StructDecl`, `EnumDecl`, `EnumVariant`, `FieldDecl`, `TypeRef` |
| statements | `Binding`, `Return`, `LoopControl`, `ExprStmt`, `IfBranch`, `IfStmt`, `CaseStmt`, `CaseArm` (with `guard`), `WildcardPattern`, `LiteralPattern`, `VariantPattern` (with `Slot` entries), `WhileStmt`, `ForStmt` |
| expressions | `Literal`, `TypeName` (name, span; JSON type arguments only), `ConstRef` (linked name, span; made by the linker for a read of a constant), `NameRef`, `Call`, `EnumConstructor`, `FunctionRef`, `Invoke` (target, args, span), `NamedArg`, `Construct`, `StructUpdate` (target, named args, span, `visible`: the linked struct names the file may update, set by the linker; the `value.with(f: x)` copy), `ListLit`, `MapLit` (with `MapEntry`), `FieldAccess` (target, name, span, `resolved`), `MethodCall` (target, name, args, span, `resolved`), `TypedTarget` (expression, type; checker-made receiver), `Interpolation` (parts: strings and expressions, span), `BlockLit` (params, body, span) with `BlockParam`, `IndexAccess`, `TryExpr` (operand, span), `Unary`, `Binary` |

Design points: one `TypeRef` covers `Int`, `List[Int]`, and `List[List[Int]]`; one `Literal` covers integers, floats, strings, booleans, and `nil`; grouping `( expr )` produces no node; `Call`/`Construct` store the name as a string; `Unary`/`Binary` store the operator as the token kind (`plus`, `and`, `equal`); `Absent` is `Optional.Absent`.

## Parser (`compiler/parse_base.agc`, `compiler/parser.agc`)

`parse: List[Token] -> Result[Program]`. Recursive descent over the token list, with the context (`Env`), a position and the next free node id passed and returned:

- Precedence ladder: or → and → equality → comparison → pipe → additive → multiplicative → unary → postfix → primary.
- The pipe (`x |> f(a)`) is left-associative and builds a `Call` with `piped` set (the call's span is the right side, the inserted argument keeps the left span); `try` on the right wraps the piped call. The parser records each call it builds from `name(...)`, `Alias.name(...)` or `Result.Ok(...)` as parenthesized (a `do` block rebuild keeps the mark); the right side must be one of those and not already piped, else `PARSE-PIPE-TARGET` at the right side. Every place that rebuilds a `Call` (the linker, the `do` block) must pass `piped` along.
- Arithmetic levels are left-associative; equality and comparison take a single optional operator, so `a < b < c` and `a == b == c` are `PARSE-CHAINED-COMPARISON`, while `a < b == c < d` is valid.
- Nesting limit (`nesting_limit`, 1000): `enter` counts each statement, expression, prefix operator and type. A chain of binary operators or pipes and each suffix of a postfix expression counts as one more level, and what is parsed after the k-th link starts k levels deeper (`deepen`); beyond the limit is `PARSE-TOO-DEEP` at the current token. The limit bounds the calls of the parser, not the depth of the tree: the right operand of the first link of a chain hangs below the whole chain, so nested chains can build a tree far deeper than 1,000 (measured: 1,990 for two nested chains, about 89,000 for 100). A pass that recurses on the tree needs its own stack or limit.
- Nesting limit of the checker (`compiler/check_state.agc`, `nesting_limit`, 1000): each expression and each statement counts as one level, so it bounds the depth of the tree; beyond the limit is `CHECK-TOO-DEEP` at the node, with help to split the code. Alias expansion also stops after 1,000 type references, so repeated aliases cannot grow exponentially in the checker. The parser limit does not bound the tree (a nested chain hangs below its first link), and the checker needs up to 5 VM frames per level (builtins with the nested call as first argument; 3 for `if`, calls and method chains; 6 for each nested block), about 5,000 of the 10,000 at the limit.
- Top level accepts def/struct/enum/type-alias/import, constants (`NAME = value`, `ConstDecl`) and exported forms of def/struct/enum/type-alias/constant. `type` is contextual: it starts an alias declaration only at the top level and remains an ordinary name elsewhere. `case` uses an optional `do`, `->`, and `end`; `while` and `for` headers also take an optional `do`. A case arm body is either a NL and a block, or one simple statement on the arrow line followed by more statements. A qualified function name without `(` is a `Call` with no arguments. `import` has two forms: `import Alias from "path"` and `import {a, B as C} from "path"`; a string right after `import` (the path-first form of earlier versions) is `PARSE-UNEXPECTED-TOKEN` at the string, with a help that shows the first form; `from` and `as` are plain `name` tokens read by their text, so they stay usable as names. Qualified names cover imported types, enum constructors/patterns, calls and function references. Module nodes must pass through the linker before check.
- `.with(` (the name is exactly `with`, then `(`) makes a `StructUpdate`: named arguments only, at least one, a trailing comma and blocks allowed in the values; `value.with` without `(` stays a field access, and `with` is not a reserved word.
- A statement starting with `name` is a binding when the next token is `=` or `:`; otherwise it is an expression.
- Stray `NL` tokens are skipped at the top level and between statements (see "Lexer gotcha: stray NL tokens" in `references/frontend.md`).
- Doc blocks (roadmap 22a): the parser takes an optional `DOC` before a declaration, a field or a variant, and accepts the block only when its `next` is `code` and one `NL` is followed by the member's first token; the text is then stored under the member's span. At the top level, a block with `next` `blank`, before any declaration and when there is no module doc yet, becomes the module doc. Anything else is `PARSE-DETACHED-DOC` at the block's span. Every other place a `DOC` can reach (a function body, inside brackets, before `end`) fails through `bail`, which turns any diagnostic whose token is a `DOC` into `PARSE-DETACHED-DOC`, except `PARSE-MISSING-BLANK-LINE`. The blank-line check counts a `DOC` as the start of a declaration, so a block right after an `end` gives `PARSE-MISSING-BLANK-LINE` at its first line.

## Linker (`compiler/modules.agc`, `resolve*.agc`, `rewrite.agc`, `linker.agc`)

`link_file` links imports before `check`: `modules.agc` reads the files (with an explicit stack), `resolve.agc` and `rewrite.agc` give every name its linked name. The std-only guard lives in its name resolution: a two-part name whose module is in the std-only set of the catalog (today `HttpWire` and `LogRegistry`) and that no import alias names is `CHECK-UNKNOWN-NAME`, with a help that shows the import of its std module (`import HTTP from "std/http"` for `HttpWire`, `import Logger from "std/logger"` for `LogRegistry`), unless the module was embedded from `stdlib/`. A user file, a relative import and a `pkg/` module all get it. `HttpWire` is also left out of `help`, its JSON and every "did you mean". The linked program carries the root file's `docs` and module doc; nothing after the parser reads them.

Names imported with `import {a, B as C} from "path"` live in a per-file table (local name to the module key and the original name), filled once the module is loaded, because the checks need its exports. In order, per entry: `CHECK-IMPORT-NAME` at the original name (unknown or private), `CHECK-IMPORT-RENAME` at the local name (a type name must start with a capital letter, a function name must not), then `CHECK-REDEFINED-NAME` at the local name against the file's declarations, aliases, other named imports, builtin functions and the reserved type names. Resolution maps a name without a dot found in the table to the linked name of the export (with the same kind check as `Alias.name`), the rewrite turns `Color.Red` and `Color.Red(x)` with `Color` an enum in the table into an enum value, and the `visible` list of `.with` also takes the targets of the table.

## Checker (`compiler/checker.agc` and the `check_*.agc` files)

`check(linked, settings) -> Checking.Done(Checked) | Failed(Problem)`. Registration first (`check_register.agc`), then bodies, stopping at the first error:

- Enum names are registered before struct fields resolve; struct names precede field resolution; enum payload templates resolve after all struct names exist; function signatures follow. This allows forward references and generic enum payloads.
- Catalogued builtin function names cannot be redefined. `ok` and `error` are additionally reserved on locals, parameters, loop variables, and fields.
- Types are the `Type` enum of `compiler/types.agc`: the primitives, `List`, `Map`, `Set`, `Result` and `Task` of a type, structs and enums by linked name (an enum carries its type arguments), and type variables during payload registration.
- A piped builtin call that has a method form for its first parameter's type is `CHECK-PIPE-METHOD` at the call span (after the call checks, so type and arity errors come first). The kind comes from the builtin entry's first parameter; the help text is cut from the source, starting a piped call or piped `try` at its piped argument and wrapping it in parentheses.
- Builtin module calls keep their dotted name. The checker reads arity, signature and fixed types from the catalog (`builtins_data.agc`); generic rules are explicit rule functions (`check_rules.agc`, `check_list.agc`, `check_collections.agc`, `check_args.agc`). Lowering reads the same entry's implementation key and trusts checked arity.
- String operations count Unicode characters. Numeric conversions accept signed decimals: non-bang forms return Result; bang failures remain `RUNTIME-INVALID-NUMBER` / `RUNTIME-INTEGER-OVERFLOW`. IO.gets returns Result[String]; IO.gets! retains the old String/EOF diagnostic behavior.
- Expected types must reach builtin calls for contextual ok/error and unwrap/default. An untyped error is CHECK-RESULT-TYPE, and a `Channel.new` with no expected type is CHECK-EXPECTED-TYPE. `try` requires a Result-returning function and a Result operand; its payload type may differ from the enclosing success type. It does not guarantee a return. `try` also works in a block whose expected `Fn` has a fixed `Result` type (`Test.test`, `File.each_line`). The last expression of such a block is checked as a completion value (7.2.1h), so a Void or non-Result last expression is `CHECK-TYPE-MISMATCH`, not `CHECK-VOID-VALUE`. The help `give a Result with ok() or error("message")` (`ok(...)` when `T` is not Void) is given for every mismatch whose expected type is a `Result` and whose actual type is not one, a block's last expression or `x: Result[Int] = 5` alike. `try` also works in a block whose `Result[T]` has an inferred `T` (17a `Task.map`; 15i `File.open` blocks reuse it): the call rule (`check_task_map` in `check_collections.agc`) gives the block the expected `Result[R]` from the expected `List[Result[R]]`, else `Result[Unknown]`, and `check_block_body` turns `Result[Unknown]` into the `Slot.InferResult` slot (`check_state.agc`): `result_context?` accepts it, the first `return` or the last expression must be a `Result` and fixes its type, and every later value must agree. A first value of `error(...)` has nothing to infer from, so it stays `CHECK-RESULT-TYPE` (annotate the variable).
- Scopes are a stack of maps holding `name -> (type, immutable?)`. The `for` variable is immutable.
- A plain binding to a visible name is an update and must keep its type; an annotated binding to a visible name is `CHECK-ANNOTATION-ON-EXISTING`; a fresh name that is already visible is `CHECK-SHADOWED-NAME`.
- The result (`Checked`) holds the type of each expression and block by node id (the literal 2^63 under unary minus is never recorded; lowering handles it by rule), what each method call or field access resolved to, and the linked names of the module constants in initialization order. Lowering trusts it and does not re-check types.

## Compiler prelude (`compiler/prelude.agc`, `prelude_data.agc`, `check_prelude.agc`, `stdlib/prelude/`)

A prelude method is a builtin written in Agentica (`docs/future/25-ruby-typed-idioms.md` 25.6): its catalog row has `Rule.Prelude` and an empty implementation key, `prelude_data.agc` says which file and function run it (`plain`, `limited` for a variable that only some types may take, `chosen` for one function per type of the variable), and the body is a `def` in `stdlib/prelude/<file>.agc` that names its type variables (`A`, `B`, `K`, `V`) in annotations. To add one: the row in `builtins_data.agc` (sorted by name), the entry in `prelude_data.agc`, the body, and the tests of 25.6 (a spec case for each rule, a VM golden for the results and the errors, a step count in `tests/fixtures/vm/prelude-cost.agc`).

- `Rule.Prelude` (`check_prelude.agc`) checks the arguments left to right, binds the type variables (a block gets the types known so far), checks the limits (`CHECK-TYPE-MISMATCH` at the argument that bound the variable) and records the body by call id (`St.bodies`, `Checked.bodies`).
- After the program, `Prelude.attach` reads `std/prelude/<file>.agc` for the files the program used, parses it from the next free node id, keeps the functions called (named `@prelude::file::name`, `Ir.prelude_name`) and checks them with `Cx.prelude` set (a type variable may be a Map key or Set element; `__fail_arg` is known). A program that calls no prelude method reads no prelude file. `std/prelude/...` is not importable.
- Lowering turns the call into a plain `call` (never a `tail-call`) with the span of each argument after the span of the call, adds the files as sources named `<prelude>/file.agc` with no text, and pins every span of their functions to 1:1. The VM reads the name, flags the functions (format 6) and reports an error inside a run of prelude frames at the call of the program (`docs/vm/03-ir-and-bytecode.md`).
- A body calls builtins only (no other prelude function), never `concat`, `take`, `drop`, `reverse`, `sort`, `Map.keys`, `Map.values` or `Map.delete` inside a loop or a callback (`tests/test_stdlib_prelude.py`), and uses `__fail_arg(code, index, message)` to fail at argument `index` of the call. `__fail_arg` is unknown to a program (`CHECK-UNKNOWN-NAME`) and hidden from `agentica help`.
- The compiler itself must not call a prelude method until `bootstrap/stage0.agcb` is refreshed.

## Lowering (`compiler/lowering.agc` and the `lower_*.agc` files)

`lower(linked, checked, catalog) -> Lowered.Done(Ir.Program) | Failed(Problem)`. One IR function per function declaration in declaration order, then (with module constants) one per kept constant in initialization order, then `<start>` when the program has globals, then the block functions; `entry` is `main`, or `<start>` when it exists (`references/vm-lowering.md`). A read of a constant is `global`, or a `const` for a scalar literal. Slots: parameters first, then locals, which are resolved statically and freed when their scope ends, then temporaries with a stack discipline so a call window is always the highest live slots. A new local is lowered straight into its slot; an assignment to an existing local goes through a temporary and `move`. Unsupported forms or types are `LOWER-UNSUPPORTED` at the node span; a failed internal assumption is `LOWER-INTERNAL` at the program span. A `MethodCall` or `FieldAccess` with `resolved` set lowers its resolved node without a step and checks the outer node's type, because the synthetic call that the checker builds is not in the types table; a `TypedTarget` lowers its expression and checks its recorded type. `lower_text.agc` prints the IR (`--dump-ir`).
Builtin records the VM knows (`FileInfo`, `Header`, `HttpResponse`, `HttpClientOptions`, `ProcessOutput`, fields in record order) are appended to the program's structs when a checked type mentions them, with the records they need (`HttpResponse` needs `Header`); the C side finds them by name (`agc_builtin_struct`).

A change to the lowering (a bug fix, a builtin name in `VM_BUILTINS`) changes `compiler/lower_tables.agc` or the `lower_*.agc` file and a golden in `tests/fixtures/frontend/lower/` in the same PR.

## Bytecode writer (`compiler/bytecode_writer.agc` and the `bytecode_*.agc` files)

`write(root_dir, program, version) -> Written.Done(bytes) | Failed(Problem)` resolves labels, merges adjacent `step`s (split above 65535), and builds the constant pool, builtin imports (name and arity) and the span table (span 0 is the program span; multi-span instructions use consecutive entries). It gives the `.agcb` bytes of `docs/vm/03-ir-and-bytecode.md` 4.6; the C loader is the only reader. `tests/test_frontend_bytecode.py` compares the writer with the frozen bytes of the original writer, and its `OPCODES` with `agc_opcode` in `vm/value.h`. The version of the header is the `VERSION` file, an input of the writer (`Settings` in `compiler/link_env.agc`), never a constant. The file is format version 5: after the Updates section the writer writes the Globals count (`u32`, the number of slots of the module constants, 0 for a program without any; 44a2), and the opcode list ends with `global` and `global-set`, which the lowering emits for a constant read and for `<start>`. The IR holds the interned struct updates (struct index and updated field indexes, one `STRUCT_WITH` operand each). `BYTECODE-LIMIT` (at most 65535 each) for structs, enum variants, fields in one struct, payload items in one variant, module constants, JSON field types, struct updates and registers in one function, and for more than 1024 nested List and Map levels in a JSON field type; an impossible IR is `BYTECODE-INTERNAL` at the program span.

## Builtin catalog (`compiler/builtins.agc`, `builtins_data.agc`, `builtin_model.agc`)

One catalog of name, parameters, result, generic rule tag, implementation key, effects, and description, as data edited by hand (`builtins_data.agc`) with the lookups in `builtins.agc`. The std-only modules (`HttpWire`, `LogRegistry`) are only callable from `stdlib/` (they are left out of help and suggestions). The catalog serves the checker, lowering and help; the shared type printer and `did_you_mean` (`suggest.agc`) keep help and checking consistent. Effects are informational only, except that a builtin with no effects whose result is unused is `CHECK-UNUSED-VALUE`: the `Test` assertions carry the effect `test` so they may stand as statements. `Test.eq` uses the rule `TestEq`: both arguments have one type that is a data type (the types with `to_s`, which are the §25.4 equality set plus `Json`); `TestCase` is an opaque type and `Test` is a reserved name. Every entry's implementation key must be in `VM_BUILTINS` of `compiler/lower_tables.agc` (`tests/test_frontend_catalog.py` checks the catalog) and run in a golden fixture; do not add test-only exports.

A builtin can have several signatures (alternatives by arity): the checker and lowering use the same selection. Map.get/2 returns Result[V]; Map.get/3 returns V with an eagerly evaluated default. Text help lists both signatures, and its JSON help carries overloads; single-signature JSON output is unchanged. List.repeat count errors are RUNTIME-INVALID-COUNT at the argument span, with a 1048576-element cap. List.set reuses RUNTIME-INDEX-OUT-OF-RANGE. Map.delete removes both hash storage and insertion-order keys.

## Command line (`compiler/cli.agc` and `cli_*.agc`)

`run(settings, words, hand_off) -> exit status`; the program is `dist/agentica`. `test` runs the BDD driver `compiler/bdd_driver.agc` (`references/bdd.md`). It reads the file (a missing file prints one plain line and exits 2), then links, checks and lowers it, and hands the bytecode to the VM. A diagnostic is printed in the plain form (header, message, source line, caret run) on stderr with exit 1. `--dump` pretty-prints the checked tree instead of running it; `--dump-ir` prints the lowered program. `compile FILE -o OUT` (first argument only, exactly that shape, else usage exit 2) checks, lowers and writes bytecode, and it cannot be combined with `--dump` or `--dump-ir` (usage, exit 2); lowering diagnostics exit 1, an unwritable output prints one line and exits 2. Arguments after the source file reach the VM as `System.args`, and the command exits with the VM's code. No source file exits 2. `check` never runs; --ai/--json use the same structured diagnostic. `help NAME --json` reads the catalog without a source file (unknown target exits 2); `help` alone (exit 0) prints the command summary and the builtin namespaces. `--help` and `help` share one text. Help and test handle trailing style options; options on other commands precede the command/file so program args stay intact. --max-steps accepts a positive integer and reaches only the VM. --allow-run enables Process.spawn and, for `test`, reaches step handlers and programs under test; check and help need no flag. `tests/fixtures/cli/forms.json` freezes the forms (`tests/test_cli_forms.py`).
