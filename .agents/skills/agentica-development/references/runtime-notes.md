# Runtime and library notes

Notes on the language rules of each library area: what the checker enforces and what the VM keeps. VM internals are in `references/vm.md`. Read the section for the area you are changing.

## Result, propagation, and runtime bounds

- `Result[T]` is builtin, with String errors and contextual `ok`/`error` typing. Forward expected types through the shared call path; do not add global inference or dummy payload types. Untyped errors are `CHECK-RESULT-TYPE`.
- `try` is a unary expression node. It requires a Result-returning function (`CHECK-TRY-CONTEXT` otherwise), unwraps successes, and returns errors through the current function's escape. It does not guarantee a return.
- IO.gets now returns Result[String]; IO.gets! is the old String-returning/halting form. Migrate callers in tests/eval/tasks as well as examples, without repairing intentional starter bugs or changing hidden cases. Non-bang conversions recover only their documented failures.
- Function suffixes allow whitespace before `(`; `!=` remains an operator. Empty map inference uses `CHECK-EMPTY-MAP-TYPE`.
- `--max-steps` counts every expression/statement entry, including loop conditions, per run. The CLI validates the input; check never executes. This is not a blocking-I/O timeout.
- A rebase changing AST/diagnostic layouts may leave stale ignored Racket bytecode. For an instantiate-linklet struct mismatch, use `make clean && make build && make test`; rebuild the binary with make exe before evaluation.
- `tests/eval/diagnostics.py` counts the diagnostics agents saw in `tests/eval/results` (see `docs/eval.md`). It counts only bash commands that run `agentica` or `racket ... main.rkt`. Its tests run with `cd tests/eval && python3 -m unittest`; they are not part of `make test` or CI.

## Stdio bytes and flushing

- `IO.read()` remains the all-text-until-EOF API. `IO.read_bytes(count)` returns Result[List[Int]]; wait for count bytes or EOF, return short/empty success at EOF, and do not consume input for zero or invalid counts. The fixed 1 MiB per-call cap prevents eager allocations from arbitrary Int sizes; larger streams use repeated reads. Port read failures are local Results, not exceptions around argument evaluation.
- `IO.flush` flushes stdout and returns completion. Do not auto-flush other output functions or close ports. All blocking stdio calls remain without timeouts.

## JSON (phase 5f)

- Typed decoding (5f2) uses a type-expression AST node accepted only in JSON type argument positions. JSON.decode returns located-path Result errors for bad data, validates signed Int/finite Float bounds, and ignores extra fields. Recursive type validation visits each struct once. Decoded map keys are sorted. JSON.schema uses the same eligibility check, emits required fields/64-bit bounds and $defs/$ref for nested or recursive types. Builders construct opaque Json directly; JSON.from shares encode eligibility and non-finite diagnostics. Builtin record declarations participate in decoding and schemas.

- `Json` is opaque, not primitive for equality. Reserve `Json` and `JSON`; all calls use existing parser/AST forms. The catalog has nine JSON functions; `json-encode` is the only new generic checker rule.
- Recursively check encoding eligibility, including declared struct fields and empty containers. A seen-struct path prevents infinite recursion without skipping other fields. Results and Int-keyed maps are CHECK-NOT-ENCODABLE.
- False/null are present values. Int extraction is signed 64-bit and rejects decimal/exponent forms; Float extraction permits integer conversion only if finite. Parse rejects non-finite numbers, while large integer Json payloads remain valid.
- Encoding writes objects in stored map/declared field order. Non-finite Floats halt with RUNTIME-JSON-ENCODE at the call span. Debug output is `<Json>`, not the host contents.

## Collections and algorithm examples (phase 5n, primitive operations)

- `List.map/filter/reduce` infer input element types from exact callback signatures, including empty lists. Reduce is a left fold with accumulator first; its callback result must equal its accumulator type and supplies context for the initial value. Map rejects Void results. Traversals preserve inputs and order and cost O(n) excluding callback work.
- `List.sort/sort_by` are stable, order strings by code point and put NaN last. The checker allows only Int, Float or String elements/keys. sort_by calls the key once per element, then sorts the cached keys; the key callback's parameter type types an empty input list.
- String search and conversion builtins: index_of returns character positions (empty part is ok(0)); at/code/from_code report errors at the argument span; from_code rejects surrogates. Float.to_int/to_int! share `fallible`: NaN/infinity give RUNTIME-INVALID-NUMBER, out-of-range truncation RUNTIME-INTEGER-OVERFLOW. `Float` works as a builtin module prefix because catalog names are full dotted strings.
- Time and Random: each run seeds its generator from `--seed` (0..2^31-1) or OS randomness; the VM uses xoshiro256** with one generator per task (`references/vm.md`). Random.int is uniform over the full Int range; min > max is RUNTIME-INVALID-RANGE at the call. `agentica --seed N test` passes `--seed N` to the runner, each scenario VM and each program under test, so handlers and programs under test draw the same sequence.
- `List.concat/take/drop/at` are implemented through the catalog and generic checker. Concat propagates expected types and can infer an empty first list from the second. Take/drop accept all nonnegative Int counts, clamp to length, and report RUNTIME-INVALID-COUNT at negative counts. At propagates the expected element type and reuses RUNTIME-INDEX-OUT-OF-RANGE at the index argument. Inputs stay immutable; concat costs O(length of first list), and take/drop/at are O(n).
- `List.append`, `set`, `repeat`, and `reverse` preserve inputs. Indexing and updates remain O(n); repeat is capped at 1048576 and reports RUNTIME-INVALID-COUNT at the count argument. List.set uses the existing index diagnostic at the index argument.
- Catalog entries have an automatic alternatives field. Only catalog initialization fills it; builtin-ref optionally selects by arity. Map.get has two signatures: Result[V] with two arguments, V with an eagerly evaluated default with three. Text help lists both; its JSON help has an overloads array, while existing single-signature help stays unchanged. Do not add user-function overloading.
- Generic rules propagate expected types into list construction/updates and Map.get. Keep false/nil lookup payloads distinct from absent keys. Map.delete updates both the hash and insertion-order keys; reinsertion goes last. Map.values follows Map.keys order.
- `examples/knight-tour.agc` uses degree-ordered backtracking for open tours, sizes 1..8. `examples/traveling-salesman.agc` searches optimal directed circuits over 1..8 cities with nonnegative bounded Int weights. The examples tests validate complete routes and known optimal costs with a 5000000-step budget. A runtime limit is not an unsolvable-result signal.
- Callback operations remain pending in 5n and require 5j; these primitive operations do not. Grammar and programming reference are kept together; stages.md includes the catalog arity contract.
- `examples/maze-bfs.agc` demonstrates Map.get/2 for discovery, Map.get/3 for passable cells, and Map.delete for a numeric-keyed FIFO queue. Rectangular grids are capped at 32×32; tests check legal shortest paths and distinguish invalid input from an unreachable goal. Queue deletion is O(n), so do not claim linear runtime from BFS alone.

## Ranges (phase 8a)

- `a..b` / `a...b` are `binary` nodes with op `'dot-dot` / `'dot-dot-dot`, parsed by `parse-range` above `parse-or` (one operator, no chaining). The checker type is the symbol `'Range` (in `reserved-type-names`, printable, `==` allowed, not encodable). `for` over a Range binds an `Int`. `Range` and `Int` are method modules, so `r.size` is `Range.size(r)` and `3.times` is `Int.times(3, f)`; the catalog rows use the generic `#f` rule (a block gets its `Fn[Int, Void]` from the parameter).
- VM: see `references/vm.md` (counter loops, `RANGE`/`RANGE_BOUNDS`, counting native frames).

## File modules

- modules.rkt links parsed files before checking: canonical paths deduplicate imports and detect cycles; aliases resolve only exported declarations. Dependencies get unique internal identities while root names remain stable for CLI entrypoints. Preserve every original span when rewriting nodes; never restart evaluation for imported calls/tasks. Imports resolve relative to their source, not cwd. An import path has no extension: `module-file` appends `.agc` before resolving, so module keys, std/ registry keys and span source names stay real `.agc` file names; a path ending in `.agc` gives `CHECK-IMPORT-PATH` with a help showing the path without it, and an empty path, a trailing `/` or a dot in the last part give the same code. Imported types get an internal `@N::Name` identity; human text (printing, `to_s`/`inspect`, checker messages through `type->string` and `display-name` on struct, enum and function names, the VM tables) shows it through `display-name` in builtins.rkt, so `Point` from any module prints `Point`; `did-you-mean` keeps only candidates with the same `@N::` prefix as the name (builtins go in `#:shared`) and suggests their display names. Keys stay linked: `JSON.schema` `$defs` keys and `$ref`s keep the `@N::` name so two imported `Point`s never collide. Alias/declaration collisions and builtin-name redefinitions are rejected before renaming. as is contextual, import/export are keywords.
- CLI check/run/dump/compile and the BDD driver's step program share this resolver. Raw import/export nodes passed directly to check give CHECK-MODULE-CONTEXT. Exported signatures may mention private types; importers cannot name/construct those types. `std/` reads compile-time embedded Agentica sources from stdlib.rkt, with virtual source names and no filesystem fallback. Add shipped modules to its explicit registry; embed-source tracks external source dependencies with register-external-file. `pkg/` searches entrypoint-local agc_libs, absolute AGENTICA_PATH roots, user data and Unix system data; first existing file wins. Skip missing candidates before normalize-path (it fails for absent parent directories); validate namespace components and canonical symlink containment. Other paths remain source-relative. No package registry, wildcard imports, module state, cycles, or receiver attachment.
- tests/modules-test.rkt owns linking/visibility, cross-file diagnostics, shared task budgets, a step handler imported under another alias, and the combined JSON example. Its CLI test honors AGENTICA_TEST_EXECUTABLE for compiled CI coverage. Unknown dotted calls without a matching import alias pass to the checker so misspelled builtin calls retain CHECK-UNKNOWN-NAME; unknown qualified type aliases remain CHECK-IMPORT-NAME.

## Methods on builtin types

- The parser makes `method-call` for `x.name(args)` (except `.call(`, which stays `invoke`) and `field-access` for `x.name`. Method names may carry `?`/`!`.
- The checker resolves methods by the receiver's static type (`method-modules`, `method-aliases`, `catalog-method` in checker.rkt). A catalog function is a method only when its first parameter has the receiver's type head. Resolution builds a synthetic `call` whose first argument is a `typed-target` (the receiver plus its already-known type, so chains are checked once) and stores it in the node's mutable `resolved` field; `to_s` on String stores the `typed-target` itself. Lowering lowers only `resolved`; `typed-target` does not count a step. Builtin diagnostics keep working because they read `call-args` spans from the synthetic call.
- Field access on a struct is unchanged; on anything else it is a zero-argument method. `CHECK-NOT-A-STRUCT` no longer exists; unknown methods are `CHECK-UNKNOWN-METHOD` with did-you-mean or the method list.
- `CHECK-UNUSED-VALUE`: an expression statement whose (resolved) call is a builtin with no effects, a non-`!` name and a non-Void result. `match` patterns on `field-access`/`method-call` need a `_` for the auto `resolved` field (modules.rkt).

## String interpolation

- The lexer scans string text in `scan-string-body!`. `#{` emits `interp-start`/`interp-middle` with the text so far and pushes a `(#\# string-start)` frame on `delimiters`; the `}` that meets that frame resumes string scanning, and the resumed `interp-middle`/`interp-end` token starts at that `}` so parse errors point at it, and the closing quote emits `string` (no interpolation) or `interp-end`. Newlines and EOF inside an open frame are `LEX-UNTERMINATED-STRING` at the string start. `\#` escapes `#`.
- The parser builds `interpolation` with text and expression parts (empty text pieces dropped). The checker checks each expression with no context (Void is rejected, and `ensure-printable!` rejects types without `to_s`: functions, tasks, handles) and types the node as String; the VM inserts each value in its `to_s` form (strings raw, `Json` as JSON text, others in the inspect form).
- `puts`/`print`/`IO.puts`/`IO.print`/`IO.warn` take `T` with the `show` rule tag, which only calls `ensure-printable!`; the VM writes the `to_s` form. `x.to_s` resolves through `method-aliases` for String/Int/Float; for any other printable type `check-method` records a one-part `interpolation` node, so `x.to_s`, `"#{x}"` and `puts(x)` share one text form. `printable-type?` requires printable type arguments and checks each struct or enum declaration once by name (type variables count as printable), so non-regular recursive enums terminate. Only `.to_s` (a resolved interpolation) is `CHECK-UNUSED-VALUE` as a statement; a written `"#{x}"` statement is not. A struct field named `to_s` stays a field. `x.inspect` follows the same path but records an `inspection` node, which prints the inspect form; a struct field named `inspect` also stays a field.

## Blocks and closures

- Lexer: `def struct enum if while for do` push a `(kw . position)` frame on `delimiters` and `end` pops it, so NL is emitted when the stack is empty or its top is a keyword frame. That keeps statement newlines inside a block written within `(...)`. Keyword frames left open at EOF are not a lexer error (the parser reports `PARSE-UNCLOSED-BLOCK`); a `)` that meets a keyword frame is `LEX-UNMATCHED-DELIMITER`. `|` is the `pipe` token; `||` stays `or`.
- Parser: `parse-postfix` turns `do` after a `call`, `method-call` or bare `field-access` into a `block-lit` appended as the last argument. `allow-blocks` is off while parsing a `case` scrutinee, a `while` condition and a `for` iterable, and back on inside `(...)`, `[...]` and argument lists. Only the direct statements of a block body (`(parse-block 1)`) may end at `end` instead of NL, which allows `do |x| x * 2 end`; `parse-block`/`parse-case-body` reset `block-depth` to 0 for nested bodies. `check-builtin-call` raises `CHECK-BLOCK-TARGET` when a block meets a non-`Fn` last parameter, before any rule runs.
- Checker: `check-block-body` takes known parameter types and result (or #f). With no known result, `current-result` is `'infer`: the first `return` or the last expression fixes it. `capture-boundary` holds the scope depth at the block; assigning to a name found below it is `CHECK-CAPTURED-ASSIGNMENT`. List callback rules check the list first when the callback is a block, then the block with the element type; the `&f` path is unchanged.

## Hints for foreign habits

- `foreign-names` and `foreign-methods` in checker.rkt map names from other languages to a help text. They win over did-you-mean for `CHECK-UNKNOWN-NAME` (names and calls), `CHECK-UNKNOWN-METHOD` and a bare type name such as `None`. `conversion-help` explains a `Result[T]` found where `T` is expected. The parser gives `elif`/`elseif` and `else if` their own message and help (parser `bail` takes `#:help`). Tests assert the code and a regexp on the help, never the full text. The parser also hints `let`/`var`/`val`/`const`/`match` used as keywords, `when` in a case arm, `then` after an `if` condition, `fn(...)`/`lambda` lambdas, `loop do`, `break`/`next` before more tokens, `if x do`, a trailing `if`/`while` modifier (in `expect-statement-end`), `Module.fn arg` and a `do` with no call before it. For an unknown plain name the checker prefers did-you-mean over `foreign-names`, so `next` near a visible `nexts` still suggests `nexts`. modules.rkt `bail` takes `#:help` too (an unknown alias in expression position says it is neither an import nor a local enum; `Result.X` without parentheses names the Result spellings; in a type or pattern it only suggests the import).
- `break`/`next` are contextual: `parse-simple-statement` makes a `loop-control` node only when the name is followed by NL, `end` or EOF, so they still work as variable names. The checker's `loop-depth` is reset per function and per block (saved/restored in `check-block-body`), so they cannot cross a block. 
- Two spellings for Result: the parser turns `Result.Ok(...)`/`Result.Err(...)` into `ok`/`error` calls (in `parse-construct`; the local is named `member`, so use `memf`, not `member`), and the patterns `ok(v)`/`error(m)` into `variant-pattern "Result"` (`case-arm-start?` knows them). `gets`/`gets!` without `(` parse as zero-argument calls. A two-part `Enum.Variant` with no parentheses is a `type-expression` until modules.rkt rewrites it to an `enum-constructor` when the first part is a local enum; three parts (`M.Enum.Variant`) parse directly. Programs checked without linking keep `CHECK-TYPE-MISMATCH` for `Enum.Variant`.
- Ruby headers: `case`, `while` and `for` accept an optional `do` before the NL. A case arm may hold one simple statement on the arrow line (parsed at block depth 0, so it needs its NL); `case-arm-start?` only needs the pattern followed by `->`. `Module.fn` without `(` is a zero-argument `call`.

## Enums and pattern matching

- `enum-decl` and `enum-variant` live in `ast.rkt`; `case-stmt`, `case-arm`, `wildcard-pattern`, `literal-pattern`, `variant-pattern`, and `enum-constructor` are the matching nodes. The parser maps `true`/`false`/`nil` patterns to `#t`/`#f`/`'nil`, just like expression literals. `_` in a payload slot is represented by `#f` in the bindings list; it never introduces a variable.
- Generic type variables exist only while resolving an enum's payload declarations. Preserve those names while the module linker rewrites type references; otherwise `T` becomes a module-qualified ordinary type and generic enum registration fails. Imported enum references resolve `Alias.Enum`; variants need `Alias.Enum.Variant`.
- Nullary enum construction with `Option.None()` is parsed as a general `construct` node (empty argument list); module linking, checking and lowering must recognize the enum prefix. Payload variants parse as `enum-constructor`. Imported nullary calls have three segments and must be rewritten before ordinary struct constructor resolution.
- Checker enum types are nominal and retain their enum name plus resolved type arguments. Infer type variables structurally from payload types and seed inference from a matching expected enum type. `Result[T]` is still the builtin Result, but case patterns use tags `Result.Ok` and `Result.Err`; `Result[Void]` can only discard its Ok payload with `_`.
- Enum cases require every variant or `_`. All non-enum scrutinees—including Bool and Nil—require `_`. Reject repeated/covered arms, require `_` last, and validate pattern payload arity/types before checking each arm in a fresh scope. Exhaustive case branches participate in all-path return analysis.
- Keep the independent module-linker tests for exported/private enums and imported patterns.
- Stable checker diagnostics include `CHECK-UNKNOWN-VARIANT`, `CHECK-ENUM-POSITIONAL-ARGS`, `CHECK-ENUM-TYPE-INFERENCE`, `CHECK-PATTERN-TYPE`, `CHECK-NON-EXHAUSTIVE-CASE`, and `CHECK-UNREACHABLE-CASE-ARM`; tests should assert codes, not wording.

## Function values and BDD

- `&name` creates a named `function-value`; `Fn[A, ..., R]` uses the final argument as return type, and `.call(...)` is a dedicated invoke AST node. Resolve only declared functions; no closures, builtin references, function equality or JSON encoding. Inspect is `<Fn>`.
- BDD runs on the VM in Agentica (`std/bdd`, `std/test/runner`; see `references/stages.md` and `docs/bdd.md`). Specs are `.feature` files, parsed by `std/bdd/gherkin`, separate from the language parser: English subset only, one `PARSE-GHERKIN-*` diagnostic with a span, Background replay, independent outline rows; unsupported syntax is rejected, never skipped.
- A handler is `Fn[BDD.Context, List[String], BDD.Context]`: it takes the context and captures and returns the context it changed. All step text resolves before any scenario runs. Then/And/But must add a BDD assertion; an early `System.exit` never approves a step. State belongs to one scenario, which runs in its own child VM, so nothing leaks.
- Programs under test run on the host with the inherited environment, through the same Agentica command (the compiled executable, or Racket and `src/main.rkt` from source), with the feature directory as their working directory. The child VM's signal guard stops them when a scenario ends, times out or fails.
- `make test` compiles the CLI and its modules before starting parallel Racket test workers. `make test-bdd` builds the compiled CLI and runs `tests/bdd/specs` with `tests/bdd/handlers.agc`; CI runs both.

## Lightweight I/O tasks

- Task.spawn takes Fn[A, R] and one argument and returns Task[R]; await returns the cached R, including false/nil/error Results. Sleep takes nonnegative milliseconds, zero yields and negative values halt with RUNTIME-INVALID-DURATION. Reserve Task and Channel; use Todo for the demonstration struct. No CPU parallelism. Channels (17b) are VM-only builtins in `vm/channel.c`; see `docs/vm/10-io-scheduler.md` §10.2.2.
- Entrypoint return cancels pending work and closes the run's resources. A diagnostic in `main`, RUNTIME-STEP-LIMIT, RUNTIME-INTERNAL or System.exit ends the run; any other diagnostic in a task is a crash that ends only that task (phase 24, §37), and an unobserved crash makes the run exit 1 when `main` returns. Tasks inherit ports and arguments; cross-task stream ordering is unspecified.
- `std/bdd` fails a step with RUNTIME-BDD-PENDING-TASKS when `Task.pending_count()` is above zero after its handler, then with RUNTIME-TASK-CRASHED when `Task.unobserved_crash()` is `ok`. The runner skips stderr lines with `"task": true` when it reads a child's last diagnostic.
- The `task-*` goldens own task behavior. tests/bdd-integration.rkt verifies concurrent streams of a program under test and cleanup. examples/concurrency.agc is a hermetic CI smoke check.

## TCP, TLS and HTTP

- builtin-types.rkt centralizes opaque atoms and builtin record field layouts; the checker and lowering read it. Handles cannot be constructed, compared or JSON encoded. Grammar and the programming reference describe the same public API.
- TCP and TLS are C builtins (`vm/tcp.c`, `vm/tls_openssl.c`); HTTP is `std/http` in Agentica over the std-only `HttpWire` builtins (`vm/http_*.c`), imported as `HTTP`; the server (20c) runs each connection as a task in the server's task group. See `references/vm.md`.
- tests/vm-tcp-test.rkt, vm-tls-test.rkt and vm-http-test.rkt use independent Node and Python standard-library peers. CI installs Node 24 and Python 3; absence fails CI and visibly skips locally. Checked-in localhost test certificates exercise trusted TLS, untrusted certificates and hostname rejection.

## Files and paths

- File builtins are `vm/files.c` (`references/vm.md`). File reads/writes serialize on one per-handle lock and include lock wait in the deadline; a timed-out active operation closes the handle. Symlink targets resolve relative to the link's own directory, and link cycles stop at the first repeated path. The end of a run flushes stdout first, then closes open files with pool close jobs and waits for them (at most the flush limit: 30000 ms, `--flush-timeout MS` or `AGENTICA_FLUSH_TIMEOUT_MS`; then a warning line and the same exit code); other handles close on the loop thread.
- File.open accepts read/write/append modes and only regular files or links to regular files. Whole-text calls and individual stream operations cap data at 1 MiB; strict UTF-8 errors become Result errors. Dir.mkdir is recursive and idempotent, Dir.list is sorted, and Path.resolve is lexical without symlink resolution. builtin-types.rkt owns FileHandle and FileInfo registration; grammar.md and the self-contained programming reference document matching semantics.
- File.each_line (7.2.1h) is a stepper builtin (`references/vm.md`, `vm/interp.c`): it reads one line at a time through a buffer of `buffer_bytes + 1` bytes, one pool job (regular file) or one poller read (FIFO, pipe, device) per read, each with its own `timeout_ms`; the file closes on every return path, and a task cancelled while it waits leaves the handle open until the end of run, as `File.open` does. `buffer_bytes` outside 1,024 to 16,777,216 is `RUNTIME-INVALID-COUNT` at the argument, before the file opens; a timeout of zero or less is an error Result. `tests/vm-file-lines-test.rkt` (with `tests/fixtures/lines-peer.py`) and `vm/tests/each_line_test.c` cover it; `tests/fixtures/vm/file-each-line*.agc` are the goldens.
- tests/filesystem-test.rkt runs checked Agentica programs on the VM against temporary directories, including stream/whole-file round trips, error Results, metadata, paths and EOF, FIFOs on the loop (with `mkfifo` and `tests/fixtures/fifo-peer.py`, a Python reader that is slow or leaves, giving `EPIPE`; both are required in CI), a crash cancelling a parked FIFO read, and stdin on the loop. The end-of-run file flush limit is always on (`AGC_FLUSH_TIMEOUT_MS`, 30000, in `vm/port.h`); `--flush-timeout MS` or `AGENTICA_FLUSH_TIMEOUT_MS` (read in `vm/main.c`, the flag wins, a bad value exits 2) sets it, and the FIFO test there uses small values. `tests/vm-diff-common.rkt` and the Makefile clear that variable, as they do `AGENTICA_VM_TRACE`. Keep filesystem tests local and clean temporary trees on every outcome.

## Void and processes

- Void completes a function without data. Only return/Fn-result/Result/Task completion positions accept it; reject inferred Void values except statements and forwarded Void returns. Nil remains data and requires explicit returns. Main and side-effect callbacks return Void. Result[Void] success uses ok(). Migrate fixtures by meaning, preserving Nil and false data cases.
- --allow-run defaults off and reaches the VM. `agentica test --allow-run` passes it to step handlers and programs under test. The end of a run kills and reaps directly spawned children. Expected operations return Results.
- tests/process-test.rkt uses independent Node standard-library children, CLI capability checks, binary/full-duplex streams, nonzero exits, deadline policies and PID cleanup. Node is required in CI; local absence visibly skips. CI also exercises the compiled executable and examples/process-tool.agc with --allow-run.
