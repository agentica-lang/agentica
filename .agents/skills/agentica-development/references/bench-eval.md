# Benchmarks and agent evaluation

Read before running or changing `benchmarks/`, `make bench`, the HTTP benchmark or `tests/eval/`.

## Benchmarks

Speed check (7g): `make bench` (or `python3 benchmarks/run.py --runs N --size S --only NAMES --runners exe,vm,python` (`exe` is `agentica FILE.agc`, `vm` is `agentica run` on bytecode)) times `benchmarks/programs/*.agc` on each runner against the CPython versions in `benchmarks/python/`, checks that every runner prints the same output, reports `LOWER-UNSUPPORTED` programs as unsupported, and times `hello.agc` start-up apart. It is outside `make test` and CI; `BENCH_ARGS="--runs 3 --size 2"` passes options through `make bench`; record new numbers in `docs/vm-benchmarks.md`. `list-build` (n pushes, n scattered `set`s and a `for` sum) is the gate of the list representation (8d): 160,000 pushes (`--size 8`) take under 1 s, doubling n costs less than 2.5 times the time, and no other benchmark slows by more than 2%; `list-bulk` (`repeat`, `to_a`, `reverse`, `take`, `drop`, `concat`, `join`, `String.split` and `sort` of 60,000 to 500,000 items) guards bulk builds, which must stay within 1.3 times the flat array; compare against a VM built from master, alternating the runs, and time loop-bound programs under more than one link layout before blaming list code. A new program needs `def scale() -> Int` returning 1 (the script rewrites it for `--size`), a deterministic checksum line, and a Python twin that takes the size as `argv[1]`. The HTTP sanity check (20c) is apart: `python3 benchmarks/http_bench.py` (Python 3.10 or newer) compares `examples/http_server.agc serve` on `dist/agentica run` with Node `http`, a Python asyncio server and Python's `ThreadingHTTPServer` (servers in `benchmarks/http.js` and `--serve`), all loaded by the same Node keep-alive client (`benchmarks/http.js client`, 4 processes), interleaved per round, pinned with `taskset`, and each round starts only after a 5 s `/proc/stat` sample shows `--min-idle` of all CPUs idle (repeated otherwise) and is marked disturbed when outside CPU use during it is above `--max-outside`; record numbers only from an idle machine, in the last section of `docs/vm-benchmarks.md`.

## Agent evaluation

Agent evaluation (not part of `make test`): `python3 tests/eval/run.py --help`. Docker is the default; its image is built automatically when missing (and rebuilt when the typed arm finds no `mypy` in it, or when it cannot run `dist/runtime`). Allow provider credentials with repeatable `--pass-env NAME`. Optional Firejail requires `--sandbox firejail --chroot-root PATH`. `--jobs N` runs in parallel. `--check-references` grades every `reference.*` of `tests/eval/tasks/` in the Docker sandbox without a model and exits 1 on a failure; run it after any change to a task, `tests/eval/run.py`, the Dockerfile or the VM (`make eval-references` is the same with `--jobs 8`; it is not in CI). The arms are `skill`, `grammar`, `binary` (Agentica), `python` (untyped) and `typed-python` (`mypy --strict`, pinned in `tests/eval/Dockerfile`; a failing checker is a failing run, and so is a `# type: ignore` or `# mypy:` comment). A task is `task.md`, `reference.agc`, `reference.py` (typed, passes `mypy --strict` and is the reference of both Python arms), optional `start.agc`, `start.py` and `start.typed.py` (the typed arm's start when `start.py` is untyped), and `hidden/NN.in` and `NN.out`; `hidden/driver.py` (Python standard library only, run as `python3 -I -` in the grader container with its source on stdin, `NN.in` as its first argument and the solution command after it, its stdout compared with `NN.out`) is the independent peer of the integration and big-data tasks, and `hidden/timeout` raises the 10 s case limit. Containers set `TMPDIR=/tmp` (the launcher writes its bytecode there) and the image has `libgc1` and `libssl3t64` for `dist/agentica`. The details are in `docs/eval.md`.
